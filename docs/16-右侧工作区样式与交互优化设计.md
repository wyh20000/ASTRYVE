# 右侧工作区样式与交互优化设计

> 状态：主要工作区结构、单文件 Diff 导航和 Markdown Preview 已实现；保留为行为契约，剩余人工复核进入《08》批次 6。

## 1. 文档目的

本设计针对截图中的右侧工作区（文件树、文件标签、编辑器、Diff、步骤、输出和终端）进行一轮工作台化改造，目标是让它更接近 IDEA / VS Code 的项目工作区，同时保持当前 Agent 工作流可用。

本轮优先解决六个问题：

1. 文件树和文件标签使用与语言/文件类型匹配的图标。
2. 文件树、标签、编辑器工具栏和 Diff 页面形成一致的视觉层级。
3. Diff 始终以“单个选中文件”为阅读单位，不在编辑区混入本次变更的其他文件。
4. 右侧按钮和工具栏移动到稳定、可预期的位置。
5. Markdown 文件增加代码 / Preview 切换。
6. 为后续 IDEA 风格的项目工作区留出扩展边界，但本轮不引入完整 IDE 的复杂能力。

本设计只改变渲染层结构与展示交互，不改变文件读取、保存、目录刷新、Diff 数据、终端、权限和 Agent 执行逻辑。

## 2. 当前实现审计

当前 `WorkspacePanel` 已具备以下能力：

- 工作区目录读取、递归展开、文件搜索和文件变化刷新。
- 普通文件通过 Monaco 编辑器打开，支持编辑、脏状态和 `Ctrl/Cmd + S` 保存。
- Diff 使用 `latestDiff.files` 与 `activeDiffPath`，底层已经可以定位到单个文件。
- 旧版本 Diff 缺少完整两侧内容时，会通过工作区读取和 `legacyDiff` 兼容逻辑补齐。
- 步骤、命令输出和终端已有独立视图。
- `languageForPath` 已支持 TypeScript、JavaScript、Markdown、Python、CSS、HTML、YAML、Shell、PowerShell、SQL、XML、Rust、Go、Java 等语言。

当前主要问题：

- `FileGlyph` 只使用通用文件图标和少量颜色，无法明确表达当前语言。
- 顶部视图标签、文件标签、面包屑和右侧文件树的层级接近，工作区结构不够像编辑器。
- Diff 文件虽有标签，但缺少清晰的“变更文件导航”和单文件统计，用户容易误以为编辑器展示的是整批改动。
- 保存按钮使用文本形式，占用面包屑空间；文件树开关和主要工作区操作混在同一行。
- Markdown 当前只进入 Monaco 代码视图，没有 Preview。
- 右侧区域内部宽度、文件树和编辑器工具栏没有固定的布局职责，窗口尺寸变化时按钮容易漂移。

## 3. 设计原则

### 3.1 工作台优先

右侧区域按“导航、文件、编辑器、工具”分工，不把所有操作堆在一条顶部工具栏中。

### 3.2 单文件聚焦

普通文件和 Diff 都以当前选中文件为唯一内容主体。批量变更只在导航区显示摘要，编辑器不拼接多个文件。

### 3.3 稳定位置

所有会改变内容的操作都放在固定的工具栏或标签区域；保存、Preview、关闭、文件树切换使用稳定尺寸的图标按钮，并提供 Tooltip 和可访问名称。

### 3.4 保持既有数据边界

不凭文件名内容猜测不存在的数据，不新增主进程权限，不让 Preview 绕过现有工作区读取和保存链路。

### 3.5 信息密度接近 IDE，但不复制完整 IDE

本轮采用紧凑文件树、标签式编辑器和变更列表。项目索引、全局符号导航、插件化语言服务、断点调试等完整 IDE 能力列为后续阶段，不阻塞本轮交付。

## 4. 目标布局

### 4.1 工作区整体

```text
右侧工作区
┌────────────────────────────────────────────────────────────┐
│ 文件  变更  步骤  输出  终端                    [文件树]   │  ← 工作区视图栏
├────────────────────────────────────────────────────────────┤
│ [文件标签] [文件标签] [未保存标记]                           │  ← 编辑器标签栏
├────────────────────────────────────────────────────────────┤
│ 工作区 / src / components / App.tsx       [保存] [Preview]  │  ← 面包屑与上下文工具栏
├───────────────────────────────┬────────────────────────────┤
│                               │                            │
│  编辑器 / Diff / Markdown     │  项目文件树                 │
│  当前只显示一个文件            │  搜索、目录、文件             │
│                               │                            │
└───────────────────────────────┴────────────────────────────┘
```

### 4.2 固定职责

- **工作区视图栏**：只切换 `文件 / 变更 / 步骤 / 输出 / 终端`，不放保存、Preview 等上下文操作。
- **编辑器标签栏**：只管理已经打开的普通文件或当前 Diff 文件；关闭按钮固定在标签右侧。
- **上下文工具栏**：显示当前路径、脏状态、保存和 Markdown Preview 切换。
- **编辑器区**：只渲染当前文件。
- **文件树**：只负责搜索、展开、选中文件和文件树开关，不承载保存等操作。

### 4.3 尺寸建议

- 右侧工作区最小宽度保持 `380px`，建议默认宽度 `460px`～`560px`。
- 文件树宽度建议 `220px`～`280px`，允许拖拽调整；窗口较窄时折叠为 Overlay 文件树。
- 文件树行高 `28px`，编辑器标签高度 `36px`，上下文工具栏高度 `32px`。
- 正文与控件继续使用 `14px`，代码使用现有 Monaco 字体和字号。
- 文件树、标签和工具栏使用同一套 `border / surface / text` 语义令牌，不额外引入颜色。

## 5. 文件类型图标

### 5.1 图标策略

新增一个纯渲染层的 `fileKind` 映射，不改变 `WorkspaceFileEntry` 数据结构。映射优先级：

1. 特殊文件名：`Dockerfile`、`Makefile`、`.env`、`package.json`、`tsconfig.json`、`pnpm-lock.yaml` 等。
2. 复合扩展名：`.d.ts`、`.test.tsx`、`.stories.tsx` 等。
3. 普通扩展名：`.ts`、`.tsx`、`.js`、`.jsx`、`.py`、`.java`、`.go`、`.rs`、`.md` 等。
4. 未知类型使用中性的通用文件图标。

图标实现采用项目内可控的语言徽标映射：固定尺寸、短语言标识、低饱和背景和细边框，避免“通用文件图标 + 右下角文字叠层”的廉价感。图标颜色使用语义化语言色，但不使用高饱和大色块，保证深色和浅色主题都能阅读。`TS`、`TSX`、`JS`、`JSX`、`Vue`、`Svelte` 等必须有独立映射，不能因为共享编辑器语言而复用同一个文件图标。

### 5.2 最小图标覆盖

| 类型 | 示例 | 图标语义 | 建议颜色 |
| --- | --- | --- | --- |
| TypeScript / React | `.ts` `.tsx` | TS / React 文件 | 蓝色 |
| JavaScript / JSX | `.js` `.jsx` | JS 文件 | 黄色 |
| Python | `.py` | Python 文件 | 蓝绿色 |
| Java / Kotlin | `.java` `.kt` | JVM 文件 | 红橙色 |
| Go / Rust | `.go` `.rs` | 编译型语言文件 | 青色 / 橙色 |
| HTML / CSS | `.html` `.css` `.scss` | Web 文件 | 橙色 / 蓝色 |
| JSON / YAML / XML | `.json` `.yml` `.yaml` `.xml` | 配置文件 | 金色 / 红色 |
| Markdown / 文本 | `.md` `.txt` | 文档文件 | 紫色 / 灰色 |
| Shell / SQL | `.sh` `.ps1` `.sql` | 脚本 / 查询 | 绿色 / 青色 |
| 图片 / 字体 | `.png` `.jpg` `.svg` `.woff` | 资源文件 | 粉色 / 紫色 |
| 未知 | 其他 | 通用文件 | 次要文本色 |

文件树、普通文件标签和 Diff 文件标签必须调用同一个 `FileGlyph`，避免同一个文件在不同区域显示不同图标。

## 6. 文件树与标签交互

### 6.1 文件树

- 搜索框固定在文件树顶部，清除按钮只在有输入时显示。
- 目录行只负责展开/收起；文件行负责打开或激活文件。
- 选中文件使用稳定的背景和左侧强调线，不使用强阴影卡片。
- 文件名超长时截断，Tooltip 显示完整路径。
- 文件树加载、搜索中、无结果和读取失败继续使用现有状态，不改变 IPC。
- 文件树按钮放在工作区视图栏最右侧，使用图标按钮和 Tooltip，不再与视图标签争夺空间。

### 6.2 编辑器标签

- 标签显示文件类型图标、文件名和未保存状态。
- 当前标签使用 `surface-app` 背景和底部强调线；非当前标签只在 hover 时提高对比度。
- 关闭按钮始终有可访问名称；脏文件关闭前沿用现有保存/关闭逻辑，不静默丢弃内容。
- Diff 标签只显示当前 Diff 文件，不创建“整批变更”伪标签。
- 标签过多时横向滚动，不压缩文件名到不可读尺寸。

## 7. Diff 设计

### 7.1 数据与显示边界

`latestDiff.files` 继续作为变更文件来源，`activeDiffPath` 作为当前文件选择。编辑器只接收：

```text
activeDiff = latestDiff.files[activeDiffPath]
original   = activeDiff.originalContent 或兼容读取结果
modified   = activeDiff.modifiedContent 或兼容读取结果
```

不得把 `files` 数组拼接成一个 Monaco 模型，也不得在 Diff 编辑器中同时展示本次所有文件的内容。批量信息只允许出现在变更导航区。

### 7.2 变更导航

进入 `变更` 视图时，编辑器左侧显示轻量的变更列表：

```text
本次变更  3 个文件   +42  -18

M  src/components/App.tsx       +18  -4
A  src/components/Preview.tsx   +24  -0
D  src/legacy/old.ts             +0   -14
```

- 点击一行只切换 `activeDiffPath`，编辑器内容只更新到该文件。
- 每行显示状态（新增 / 修改 / 删除 / 重命名）、文件图标、相对路径和增删行数。
- 当前文件保持明显选中态；列表可滚动，编辑器滚动位置不影响列表。
- 提供“上一个变更 / 下一个变更”图标按钮，键盘可用；到边界时按钮禁用。
- 删除或关闭某个 Diff 文件只影响本次界面选择，不修改实际 Patch 数据。
- `legacyDiff` 兼容读取继续按当前文件路径加载，不提前读取整批文件。

### 7.3 Diff 编辑器

- 宽度足够时保持左右对照；空间不足时切换为 Inline，沿用 Monaco 的 `useInlineViewWhenSpaceIsLimited`。
- 保留行号、折叠、差异颜色和只读约束。
- 默认隐藏不必要的 Minimap、代码透镜和操作按钮，减少视觉噪声。
- 当前文件路径和变更状态放在编辑器上方，不重复在编辑器内容区显示。
- Diff 预览不提供普通文件的编辑保存按钮，避免用户误以为可以直接修改 Patch。

## 8. Markdown Preview

### 8.1 入口与默认行为

- 仅当当前文件语言为 Markdown 时，在上下文工具栏显示 `代码 / Preview` 分段控件。
- 普通代码文件不显示 Preview 控件。
- 首次打开 Markdown 默认进入 Preview，用户可切回代码；再次打开同一路径时保留上次模式。
- Preview 使用当前编辑器内存内容，因此未保存修改可以立即预览。
- Diff 视图保持 Monaco Diff，不在本轮把两侧 Markdown 转成混合预览。

### 8.2 渲染范围

- 复用现有 `react-markdown`、`remark-gfm` 和 `rehype-highlight`。
- 支持标题、列表、表格、任务列表、链接、引用、代码块和图片引用。
- 默认不启用任意 HTML 直出，避免 Markdown 内容绕过安全边界；外部链接使用新窗口并带 `noopener noreferrer`。
- 图片和链接沿用内容中的 URL，不新增文件系统访问能力；加载失败显示可读的占位状态。
- Preview 区使用与消息 Markdown 相同的排版令牌，但独立限制最大宽度，避免文档过宽。

### 8.3 编辑器工具栏

建议工具栏从左到右：

```text
路径面包屑        [代码 | Preview]   [保存] [更多]
```

- 保存使用图标按钮，Tooltip 为“保存文件”，保留 `Ctrl/Cmd + S`。
- Preview 使用分段控件，不用文字按钮堆在面包屑中。
- 失败提示放在工具栏右侧并截断，完整错误通过 Tooltip 查看。

## 9. IDEA 风格演进范围

### 9.1 本轮实现

- 项目文件树 + 编辑器标签 + 面包屑 + 文件类型图标。
- 变更文件列表 + 单文件 Diff。
- Markdown 代码 / Preview 双模式。
- 稳定的工具栏、文件树开关和编辑器区域高度。
- 现有步骤、输出、终端视图保持入口不变，只统一其空状态、标题和滚动容器风格。

### 9.2 后续阶段（本轮不做）

- 多编辑器分组（左右拆分、拖动标签到新组）。
- 全局搜索、符号导航、代码补全、重构和语言服务器。
- Project / Favorites / Services 等完整 IDEA 工具窗口。
- 文件历史、Git 分支与提交视图。
- 调试器、断点和运行配置。

这些能力需要新的数据协议或较大的编辑器状态管理，不应在本轮样式优化中顺带引入。

## 10. 实现边界与状态设计

### 10.1 保留的状态

继续使用现有：

- `view`
- `openFiles` / `activeFilePath`
- `dirtyPaths` / `savingPath`
- `activeDiffPath` / `closedDiffPaths`
- `legacyDiffContents`
- `directories` / `expanded`
- 终端相关状态

### 10.2 允许增加的渲染状态

- `markdownModeByPath: Record<string, 'code' | 'preview'>`
- `fileTreeWidth`（如果现有 `workspaceWidth` 不足以表达内部文件树宽度）
- `diffNavigationFocus`（只用于键盘焦点和上/下一个变更文件）
- `isFileTreeOverlayOpen`（窄窗口下的文件树浮层）

这些状态只存在于渲染进程，不持久化到主进程，不影响工作区文件和任务快照。

### 10.3 明确不改动

- `window.agent.workspace.listFiles / readFile / saveFile / findFiles` 契约。
- 文件保存的 `expectedHash` 乐观并发保护。
- `legacyDiff` 的兼容读取和 Patch 数据结构。
- 终端启动、写入、输出订阅和关闭逻辑。
- Agent 消息中的 Diff、步骤和命令块生成逻辑。

## 11. 验收标准

### 视觉

- 文件树、编辑器标签和 Diff 导航中，同一文件的图标与颜色一致。
- 右侧工作区在窄窗口和宽窗口下，工具栏、标签、文件树和编辑器均不重叠。
- 保存、文件树、Preview 等按钮位置稳定，按钮不跑到编辑器中央。
- 深色和浅色主题下，文本、图标、选中态、Diff 增删色均可读。

### 交互

- 打开文件只激活一个编辑器模型；切换标签不会丢失脏状态。
- 进入 Diff 后默认选中第一个文件；切换变更列表只改变当前文件 Diff。
- Diff 编辑器中看不到本次其他文件的内容。
- Markdown 文件可以在代码和 Preview 间切换，未保存编辑可以即时预览。
- 关闭文件、保存文件、刷新目录、切换工作区和终端行为保持原样。

### 工程

- `languageForPath` 与 `FileGlyph` 的语言映射有单元测试。
- Diff 单文件选择和 Markdown 模式切换有组件测试。
- `npm run typecheck:web` 通过。
- 相关布局测试、工作区测试和完整 `npm test` 不出现回归。

## 12. 已确认的产品取舍

以下决策已确认，进入实现时不再作为待定项：

1. Markdown 首次打开默认进入 Preview，同时提供 `代码 / Preview` 切换，并按文件路径记忆上次模式。
2. Diff 保留顶部 `变更` 视图入口，但文件选择改为左侧变更文件列表；右侧编辑器一次只展示当前选中文件的 Diff。
3. 文件图标使用更接近 GitHub / IDEA 的品牌化语言图标，优先使用本地资源或项目内可控的静态图标映射，不依赖网络加载。
4. 窄窗口下文件树改为覆盖式 Overlay；建议右侧工作区可用宽度小于约 `720px` 时启用，避免编辑器被压缩到不可读。

## 13. 稳定性硬性要求

本轮所有视觉和交互改造必须以“不破坏其他地方的逻辑”为前提，稳定性优先于还原度和装饰效果：

- 不修改 Agent 消息生成、工具执行、审批、插件、Skills、会话和模型逻辑。
- 不修改工作区 IPC 契约、文件读写权限、`expectedHash` 并发保护和终端安全边界。
- 不改变现有文件打开、编辑、保存、刷新、关闭和脏状态行为；新增 Preview 只能读取当前内存内容。
- Diff 只调整展示和选择状态，不修改 Patch 数据、不提前读取无关文件、不影响拒绝/应用变更逻辑。
- 新增状态必须限制在渲染层，并在切换工作区、会话和视图时正确清理，不能串用上一个工作区的数据。
- 所有新增交互必须有可访问名称、键盘路径、禁用态和错误态；失败时回退到现有代码视图或空状态。
- 实现按小步提交并配套组件测试、类型检查和真实窗口验收；任何回归优先回退对应视觉改动，不绕过既有测试。

## 14. 实施顺序

1. 先抽出统一 `FileKind / FileGlyph` 映射，补齐语言图标和文件树/标签复用。
2. 再调整工作区布局、文件树宽度与 Overlay 行为，确保文件读写逻辑不动。
3. 将 Diff 文件选择迁移到左侧变更列表，保留现有单文件模型和 legacy 兼容读取。
4. 增加 Markdown Preview 与模式记忆，默认 Preview，失败时回退代码视图。
5. 最后统一空状态、按钮 Tooltip、键盘交互和主题验收，并执行完整回归测试。

## 15. 文件与文件夹图标资产来源

当前文件与语义化文件夹图标采用 `material-icon-theme@5.38.1` 的 SVG 子集：

- 来源：`https://github.com/material-extensions/vscode-material-icon-theme`
- 授权：MIT，许可证副本位于 `src/renderer/src/assets/file-icons/MATERIAL-ICON-THEME-LICENSE`。
- 运行方式：只将当前工作区需要的图标随 renderer 本地打包，不从远程 URL 加载，保证离线可用和 Electron CSP 稳定。
- 映射维护：文件与文件夹类型映射集中在 `workspaceFileKind.ts`；新增图标时从同版本 npm 包的 `icons/` 目录抽取对应 SVG，并同步更新图标源模块、测试和许可证来源说明。
