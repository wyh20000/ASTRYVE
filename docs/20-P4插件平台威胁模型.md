# P4 插件平台威胁模型

> 适用范围：当前桌面仓库的本地插件、市场、MCP、Hooks、隔离插件 UI、Browser Gateway、Google 官方 Chrome DevTools MCP 适配层与凭据。不开发 Chrome 扩展、Native Messaging Host 或私有浏览器协议。

## 1. 安全目标

- 插件、市场说明、Skill、Hook、MCP 返回和未来浏览器页面内容全部视为不可信数据，不能改变系统指令、权限、审批结果、工具 schema 或安装清单。
- 主进程是插件安装、启用、权限、审批、凭据、审计和执行生命周期的唯一可信决策点。
- Renderer、插件 UI、Utility Process、外部 MCP 服务和浏览器适配器均不能直接取得模型密钥、账号凭据、完整环境变量或未授权工作区。
- 单个插件的崩溃、超时、协议违规或资源消耗不得破坏其他插件和主应用的可用性。

## 2. 资产与攻击者

需要保护的资产包括工作区文件及 Git 状态、模型 API Key、MCP/OAuth 凭据、账号数据、会话和审批令牌、插件安装来源与发布者身份、审计完整性，以及主进程的 CPU、内存、磁盘和进程资源。

攻击者可能控制社区市场源、下载包、插件 JavaScript、Skill 文本、Hook 返回、MCP 服务响应、网页内容或被注入的模型输出。攻击者可以构造路径穿越、链接竞态、摘要或签名替换、版本降级、超大或循环消息、重复调用结果、伪造协议类型、长时间不响应和连续崩溃。

## 3. 信任边界

1. **市场源 → 安装暂存区**：索引和 ZIP 均不可信；安装前核对 HTTPS 来源、摘要、包内清单身份、版本和展示权限，正式目录只接受已验证暂存结果。
2. **Renderer → Preload → Main**：Renderer 不可信；IPC 验证主框架来源、登录状态和结构化参数，Renderer 不能传入安装目标路径、账号目录或批准结果。
3. **Main → Utility Process**：主进程只发送固定版本和精确字段的协议消息；每条调用由宿主生成随机 ID，并限制为 200KB。Worker 只收到插件定义、工具参数、任务 ID 和工作区 ID。
4. **插件 → Tool Registry / Policy Engine**：插件清单只能声明宿主支持的操作和权限；运行时仍由确定性策略分类并执行审批，插件返回值不具备授权语义。
5. **插件 → MCP / OAuth**：凭据保存在系统保护存储中，只由主进程连接管理器使用；插件和 Renderer 只看到脱敏连接状态。
6. **隔离插件 UI → Main**：独立 session、专用 preload 和窄桥接；拒绝 Node、主应用 API、任意外链、下载和权限请求。
7. **Browser Gateway → ChromeDevtoolsMcpAdapter → Google 官方 MCP**：页面内容和官方 MCP 响应不可信；Gateway 必须保留权限、审批、可信页面绑定、截止时间、取消和限量输出边界。模型只获得当前回复动态目录中明确公开的宿主工具。

## 4. 已实现的强制控制

- 插件下载使用摘要校验和暂存安装；身份、版本、权限与市场展示不一致时保留旧版本并拒绝替换。
- 插件默认禁用；权限或发布者身份变化要求重新确认，官方、社区和本地来源分开展示。
- Worker 使用独立 Utility Process、环境变量白名单、入口真实路径和普通文件检查、启动/调用/心跳/停止时限。
- Worker 协议校验版本、精确字段集合、字段长度和 200KB 上限；未知、畸形、扩展 schema、超大及已完成调用结果重放会终止该 Worker。
- 三次连续启动、工具或 Hook 失败会隔离插件，立即停止该插件在所有任务中的 Worker；恢复必须由用户通过受信 IPC 明确触发。
- 工具参数按清单 schema 拒绝额外字段；模型和插件不能构造批准令牌或直接声明 Browser Gateway 与宿主专用操作。
- 审计只保存决策元数据，敏感字段和疑似 Bearer/API Key 值会脱敏；审计不可写时需要审计的授权操作失败关闭。
- 禁用、更新、回滚和卸载会停止 Worker 并关闭插件 UI；卸载可清除插件拥有的数据及连接凭据，审计记录保留。

## 5. 尚未关闭的发布风险

- **本地插件代码仍是带 Node 能力的 JavaScript。** Utility Process 提供崩溃隔离，但目前没有证明其文件、网络、子进程和系统调用受到操作系统或 Node 权限模型的完整限制。完成可靠沙箱或把可执行社区插件限制为受信发布者之前，不能勾选“插件无法访问未授权路径”，也不能把社区可执行插件作为默认推荐。
- MCP 与未来浏览器适配器是独立外部进程/服务边界，仍需真实账号、断线、重连、凭据轮换和恶意响应测试。
- 提示注入、性能压力、崩溃恢复、隐私清除以及 DeepSeek 和第二模型的真实端到端验收仍按 M17-C～H 执行。

## 6. M17-A 验证证据

- `pluginWorker.test.ts`：环境白名单、握手、取消、超时、心跳、严格 schema、超大消息、结果重放、崩溃与强制停止。
- `pluginMarketRuntime.test.ts`、`pluginHealth.test.ts`：连续失败隔离、审计、立即停止同插件 Worker 和用户恢复状态。
- `pluginInstaller.test.ts`、`pluginLifecycle.test.ts`：路径、摘要、暂存替换、更新失败和回滚。
- `pluginUiWindow.test.ts` 与 `smoke:plugin-ui`：隔离 session、窄桥接、CSP、外链和权限阻断。
- `pluginMcpTools.test.ts`、`pluginConnectionService.test.ts`：外部调用审批、脱敏审计、连接故障隔离和凭据边界。

任何测试证据只能证明列出的控制。第 5 节风险关闭前，M17-A 和第四阶段不得标记整体完成。
