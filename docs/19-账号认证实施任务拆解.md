## 2. 实施顺序

1. A：冻结登录协议和隔离清单，明确服务端/Web/桌面端边界。
2. B：完成服务端一次性授权码及 Web 短信登录，使浏览器侧能产生可交换的登录结果。
3. C：完成 Electron 回跳、会话保存与业务门禁；D 的数据隔离完成前，不能对真实用户开放解锁。
4. D：完成账号数据分区、切换和退出时资源收敛；与 C 合并通过短信端到端门槛。
5. E：接入 QQ/微信官方授权；平台资质和密钥是独立外部依赖，不阻塞前面受控环境的代码与测试。
6. F：部署、对抗测试、真实账号和页面验收后才发布。

## A. 协议与安全基线

- [ ] 定义 HTTPS 登录发起、Web 会话、一次性授权码交换、会话校验/撤销的请求、响应和错误码；服务端仅允许预先限定的 `127.0.0.1` 回调形式，精确绑定随机端口、路径、请求 ID、`state` 和 PKCE S256 挑战。
- [ ] 定义授权码过期与单次消费、并发登录请求取代旧请求、回调超时/取消、重放、错误来源和网络中断的状态机；回调 URL 不携带会话令牌。
- [ ] 明确首次登录、已有会话启动验证、会话过期、离线锁定、退出和切换账号时各服务的启停顺序，以及服务端撤销失败的提示。
- [ ] 盘点全部业务 IPC、非 IPC 事件/后台任务与持久化路径，列出未登录必须拒绝的入口及需要按账号分区的资源；保留旧全局数据但不自动归属新账号。
- [ ] 制作端到端安全测试矩阵，覆盖 Web Cookie/CSRF、回调伪造、授权码竞争、跨账号数据、任务取消和敏感日志。

完成标准：协议和资源清单可直接作为 B～D 的测试依据；任何一项身份或目录只能由服务端验证结果确定，Renderer 不提供用户 ID、数据路径或令牌。

## B. 认证服务与 Web 登录

- [ ] 在现有短信服务上新增浏览器登录请求、Web 会话、短期单次授权码及 PKCE 交换；把验证码验证结果接入 Web 流程，浏览器不直接获得桌面端会话令牌。
- [ ] 持久化并原子消费授权码，限制有效期、请求大小、频率和并发；严格校验挑战、回调地址、`state` 与所属登录请求，记录脱敏审计。
- [ ] 增加 Web 登录页：根据 `/methods` 展示可用方式、手机号发送/验证、倒计时、失败/过期/重试与完成返回客户端状态；未配置方式可见但不可提交。
- [ ] Web 端设置 Secure、HttpOnly、SameSite Cookie 和 CSRF 防护；短信接口保持原有限时、次数及 IP/手机号限流，避免账号枚举和验证码进入日志。
- [ ] 扩充服务端 HTTP/数据库测试和 Web 页面测试：错码、重放、并发兑换、错误回调、超时、Cookie/CSRF、服务不可用；测试替身仅在隔离测试环境使用。

完成标准：在受控测试环境中，Web 短信流程只能向正确发起方交付一次性授权码；无真实腾讯云配置时明确不可用，不能凭空完成真实短信验收。

## C. Electron 登录闭环与门禁

- [ ] 主进程提供受信的登录状态、启动、取消、退出 IPC 白名单；启动登录时调用系统浏览器，并为该次请求独占随机端口的 `127.0.0.1` 回调监听。
- [ ] 校验精确回调路径、端口、`state` 和时限，通过 HTTPS 用 PKCE verifier 换取会话；再次向服务端确认有效及用户 UUID 后才进入已登录态。完成/失败/取消/退出时关闭监听、作废旧请求。
- [ ] 使用受保护的本机存储保存会话；加密后端不可用时拒绝持久化，不把 token、授权码、平台凭据传给 Renderer、插件或日志。
- [ ] 在主进程统一拦截全部业务 IPC，并检查可信主框架来源与已验证会话；窗口遮挡或 React 状态不作为权限依据。覆盖发送消息、工作区、终端、设置、模型、插件、Skills 和审批等通道。
- [ ] 调整启动流程：登录确认前不初始化账号相关存储、插件、Skills 或后台任务，也不恢复旧任务；已有会话必须在线验证后才能重新开放服务。
- [ ] 客户端锁定页显示产品标识、Sign in、浏览器等待、失败和重试；认证输入只在 Web 页。背景样式、是否使用动效及实现技术待后续决定；窄窗口、键盘焦点和无视觉背景时也可操作。

完成标准：无会话、错误回调、断网或服务端撤销时，Renderer 不能通过直接调用 preload API 读取或执行任何业务能力；正常回跳后仅主进程持有凭据。

## D. 账号数据隔离与生命周期

- [ ] 以验证后的服务端 UUID 建立账号上下文；文件型数据放入独立账号目录，严格拒绝 Renderer 路径和非法 ID，旧全局数据原样保留且不自动迁移。
- [ ] 梳理并改造会话/消息 MySQL 存储：每次查询、写入与关联均约束当前账号；本地 JSON 回退也使用账号路径，避免共享全局库时串读。
- [ ] 迁移设置、模型配置与密钥、工作区授权、插件/Skills 安装及来源、MCP 凭据、任务持久化、审计和缓存到账号作用域；确需全局的设备级设置单独列白名单。
- [ ] 退出/切换时先锁定新业务调用，停止生成、Agent 任务、Worker 和外部连接，释放数据库/服务单例、清除 Renderer 内存状态，再装载另一个账号；旧窗口/迟到回调/在途结果不得写入新账号。
- [ ] 覆盖 A→B→A 切换、强退重启、MySQL 不可用回退、旧全局数据残留、共享插件和恢复任务的隔离测试；退出离线时先本地锁定并提示服务端撤销未完成。

完成标准：两个账号在消息、工作区、插件、配置、凭据和审计中均不可见对方数据；未登录时不会加载任何一个账号的内容。

## E. QQ 与微信官方授权

- [ ] 确认 QQ 互联和微信开放平台审核结果、桌面产品适用的授权模式、回调域名及最小必要权限；密钥只部署于服务端。
- [ ] 分别实现发起授权、随机 `state`、服务端回调和令牌交换；以平台稳定身份 ID 建立/复用账号，不依据昵称或手机号自动合并。
- [ ] 登录方式由服务端真实配置决定，未获审核或配置时显示不可用；新增已登录态下明确的跨方式绑定与冲突处理流程。

完成标准：两种真实平台授权均经 Web/服务端返回同一桌面授权码协议；任何失败都不会创建伪账号或解锁客户端。
