## 当前执行队列（2026-09-23 核对）

总计划按批次 0→2 → 3A → 3B → 4→7 执行；M16 的 Task 编号是批次 3B/4 内的依赖清单，不是要求重做已完成批次 2。当前 3A 的代码和自动化已落地，先完成其真实桌面及旧数据库验收，再进入 3B。实际顺序如下：

1. **前置核验（代码与自动化已完成）**：M16 Task 1 已保存完整官方 1.7.0 `tools/list` schema fixture、映射与失败测试；Task 2 的历史修复已按现有代码和测试逐项复核。真实模型/Chrome 验收仍留在批次 7。此前完成的 Task 5 动态目录底层不算 Task 5 完成。
2. **批次 3A 工作/对话分治**：产品选择已确认；先补固定的会话类型、项目归属与旧数据迁移；主进程封住普通对话的 Coding 权限，然后实现顶部一级切换、项目分组和底部普通对话区。跨类型切换新建会话，已有记录不转换。这是能力边界前置项，不是批次 6 的纯视觉重构。
3. **批次 3B 主链路**：在已完成的普通对话可选原生工具循环基础上，继续模型自主搜索、宿主 `browser.activate`（M16 Task 4）、动态目录与撤销审计（Task 5），按新类型分别注册工具。Task 3 整体验收仍未完成；在这一步结束前，不删旧浏览器路由或宣称自动触发可用。
4. **批次 4 浏览器正确性**：按 Task 6→9 完成可信页面绑定、对话内消歧、最小工具集和打开/等待/重试；再按 Task 10→12 完成截图、证据、终态和资源回收；最后 Task 13 删除旧路由，Task 14 自动化与真实 Chrome 验收。
5. **批次 5→7**：插件/Skill/审批、交互视觉、发布验收。Remote 认证仍是独立轨。

每项仅在代码、测试及该项所需的真实验收均具备时标为完成。当前可运行的旧浏览器路径只是迁移期间兼容行为，不代表新架构已接通。

## 1. 当前结论

P1、P2、P3 以及 P4 的插件、市场、MCP、Hooks、隔离 UI 已经具备大部分代码和自动化覆盖，但“代码存在”不等于“项目完成”。当前仍有三类发布阻断：

1. 对话发送事务、跨轮上下文和增量存储已完成代码修复；能力路由与跨会话审批等剩余 P1/P2 仍待修复和实机验收。
2. 搜索、项目、Skill、插件和 Chrome 仍由多套分支路由，尚未形成统一的模型驱动能力循环。
3. M9～M11、M13～M14 与 M16 的真实模型、真实页面、安装包和人工安全验收没有全部完成。

因此不再按旧 M12 → M17 的功能编号继续堆叠。剩余工作统一按本文件的批次 0→2、3A、3B、4→7 执行。

## 6. 停线条件

出现以下任一情况时停止进入下一批：

- 同一发送可能产生多个 generation，或任一路径没有持久终态。
- 会话切换会串附件、草稿、审批、页面绑定或项目权限。
- 无项目普通对话可通过任一直接或间接工具路径访问项目文件、终端、补丁或 Git。
- 文档、图片、网页或插件内容能够扩大工具目录或绕过 Policy Engine。
- Chrome 工具映射没有对应固定版本官方 schema 和失败测试。
- 截图只存在进程内、重启丢失，或写入失败后仍作为成功展示。
- 真实模型/Chrome 未验收却把相应里程碑标为完成。
