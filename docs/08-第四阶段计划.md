依赖关系：当前仓库按 M12 → M13 → M14 → M17 推进；外部 Chrome 扩展完成后，通过保留的 Browser Gateway、权限和审计协议单独集成。

## 3. 全阶段共同要求

- [ ] 第三方插件代码不得加载进 Electron 主进程或 Renderer。
- [ ] 插件发现、导入和清单校验阶段不得执行插件代码。
- [ ] 插件权限不得扩大当前任务权限、工作区授权或 Tool Registry 策略。
- [ ] 模型只能通过厂商官方支持的结构化工具调用接口使用插件，不从普通文本中猜测工具调用。
- [ ] DeepSeek、Kimi、OpenAI、Gemini 等模型差异只放在 Provider Adapter，插件内部协议保持厂商无关。
- [ ] 接入或修改模型工具调用前，重新核对对应厂商官方文档，并在实现计划或验证记录中保存链接和关键限制。
- [ ] 所有插件调用必须有唯一 ID、截止时间、取消信号、消息大小限制、崩溃隔离和审计记录。
- [ ] 网页、插件返回值、MCP 返回值和市场元数据一律作为不可信内容，不得改变系统指令、权限、审批策略或工具注册。
- [ ] 凭据保存到操作系统凭据库；插件不获得模型 API Key、OAuth Token、Cookie 或 Electron 对象。
- [ ] 常规窗口与窄窗口都必须可用；抽屉、详情页和弹窗不能把主内容压成不可读窄列。
- [ ] 审批使用项目自定义弹窗，摘要简短，详细参数折叠，超长内容内部滚动。
- [ ] 自动化测试不能代替真实页面和真实模型环境的人工验收。
- [ ] 未经用户明确要求，不创建 Git 提交。

推进记录（2026-09-10）：市场索引、HTTPS 来源、摘要、Ed25519 来源公钥固定、下载校验及失败缓存保留已有基础实现。本轮修复了多行 PEM 被单行文本校验拒绝的问题，并新增索引生成时间校验：拒绝无效时间、未来超过 5 分钟及超过 30 天的索引。Node 官方文档确认 `crypto.createPublicKey()` 接受 PEM 字符串且 `KeyObject.asymmetricKeyType` 可用于强制 Ed25519；M14-A 仍缺宿主配置的官方源和受保护的本地/市场安装来源持久化，暂不勾选整项。

推进记录（2026-09-11）：内置 OpenAI `openai/plugins` 的 `Codex official` 默认源，首次打开市场自动同步且不能禁用或删除。官方 marketplace 格式会转换为内部目录模型，插件清单从同步时固定的 Git 提交读取；支持现有 Skills/Tools 运行时的条目可按固定提交和逐文件 Git blob 摘要下载、校验及安装，仅含 MCP/App 的条目明确显示“待支持”。社区源的验证声明仍不会提升为官方信任。统一的本地安装来源持久化仍未完成，因此 M14-A 整项尚未闭环。

推进记录（2026-09-14）：安装来源统一为 `installOrigin`，覆盖官方、社区、GitHub 和本地目录/ZIP；现有 schema v1 市场来源记录继续兼容读取。本地导入仅保存来源类别和插件版本，不保存用户选择的原始文件系统路径；安装失败会恢复旧来源记录。自动更新明确排除本地来源，已安装列表显示实际来源。M14-A 闭环。

官方接口依据：

- [Node.js Crypto：`crypto.createPublicKey()`、`KeyObject.asymmetricKeyType` 与签名验证](https://nodejs.org/api/crypto.html)

推进记录（2026-09-14）：批次二先完成宿主专用 `external.call` 授权基础。外部调用目标只能由宿主提供并绑定确定性的 MCP 工具名，模型参数不能伪造插件、服务、账号或连接身份；`read-only` 一律拒绝，其余权限模式均只提供单次审批；策略审计仅记录目标哈希。普通插件 Worker 不能直接声明 `external.call`。MCP 工具注册与实际租约执行仍留在后续闭环。

推进记录（2026-09-14）：批次二的 Agent 接线已完成。新任务只捕获有效、已启用、显式选中且精确绑定到“已连接”服务的 MCP 工具；远端 schema 会被复制并收窄为封闭参数定义，连接身份只能来自宿主。调用复用任务级短期租约，随任务完成、失败或取消统一释放；单个服务发现或执行失败不会移除其他工具。调用结果审计只保存插件、工具、结果码和不可逆目标摘要，不保存参数、返回正文、账号或凭据。M14-D 现在仅剩 Renderer 的连接、重新授权和断开入口及相应人工验收。
