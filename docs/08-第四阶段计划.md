# 08 · 项目剩余任务与收尾计划

> 状态：当前总计划
>
> 更新日期：2026-09-23
>
> 适用基线：`main`，文档收敛提交 `38723e2` 之后
>
> 目标：先关闭对话正确性和数据契约，再完成模型驱动能力调用、Google 官方 Chrome DevTools MCP、插件验收和发布收尾。

## 1. 当前结论

P1、P2、P3 以及 P4 的插件、市场、MCP、Hooks、隔离 UI 已经具备大部分代码和自动化覆盖，但“代码存在”不等于“项目完成”。当前仍有三类发布阻断：

1. 对话发送事务、跨轮上下文和增量存储已完成代码修复；能力路由与跨会话审批等剩余 P1/P2 仍待修复和实机验收。
2. 搜索、项目、Skill、插件和 Chrome 仍由多套分支路由，尚未形成统一的模型驱动能力循环。
3. M9～M11、M13～M14 与 M16 的真实模型、真实页面、安装包和人工安全验收没有全部完成。

因此不再按旧 M12 → M17 的功能编号继续堆叠。剩余工作统一按本文件的八个收尾批次执行。

## 2. 文档权威顺序

发生冲突时按以下顺序处理：

1. 当前代码、共享类型和自动化测试描述实际行为。
2. `docs/verification/2026-09-23-剩余使用问题复核.md` 记录批次 1/2 后仍待处理的代码问题。
3. `docs/verification/2026-09-22-全局对话与交互行为审查.md` 保留历史审查基线；已修复部分不得重新列为待办。
4. `docs/superpowers/specs/2026-09-22-explicit-chrome-context-design.md` 描述模型驱动能力调用与 Chrome 安全架构。
5. `docs/superpowers/plans/2026-09-22-explicit-chrome-context.md` 描述 M16 详细实施任务。
6. `docs/22-M16-Google-Chrome-DevTools-MCP接入设计.md` 描述固定版本官方 MCP 接入边界。
7. 各 `docs/verification/` 测试单只记录验收，不定义新架构。

已删除的旧阶段计划、独立 Chrome、自研扩展、Native Messaging 和关键词路由方案不得作为开发依据。

## 3. 已完成与仍待验收

### 已具备代码和自动化基础

- P1/P2：会话、流式对话、附件、文档解析、视觉输入和供应商内置搜索。
- P3：项目授权、Policy Engine、本机与 Docker 执行、读取、补丁、diff、终端和 Skills。
- P4 M12～M14：扩展中心、插件运行时、市场、安装更新回滚、MCP 连接、Hooks、静态资源和隔离 UI。
- M16 基础：固定依赖 `chrome-devtools-mcp@1.7.0`、stdio 客户端、适配器、Browser Gateway、截图和真实本机 smoke 基础。
- 视觉系统：主题令牌、主要聊天组件、设置页、插件详情和工作区的主要改造已经落地。

### 尚未完成

- 全局对话审查中的事务、跨轮上下文和增量存储问题已有代码修复；其余能力路由与人工验收仍待完成。
- 模型驱动 `browser.activate`、统一可选工具循环和逐轮动态工具目录尚未完整落地。
- 文档与图片已进入账号级 Artifact Store；浏览器证据与工具调用的统一契约仍待批次 3/4 收口。
- 长对话已切换 SQLite 增量持久化和消息分页；仍需在真实长会话中验证 UI 性能与迁移行为。
- M9、M10、M11、M13、M14、M16 的人工验收记录尚未全部签署；早期 M12 空状态测试已被当前插件页和 M14 验收覆盖，不再单独保留。
- Remote 认证仍缺真实短信、QQ/微信、HTTPS 部署和正式账号验收；该部分属于独立发布轨。

## 4. 收尾批次

### 批次 0：统一文档和发布口径

目标：仓库只有一套当前路线，不让历史勾选框继续充当 backlog。

- [x] 删除已被覆盖的 P1/P2 历史计划、旧插件批次计划、自研 Chrome 协议和 M15 验证单。
- [x] 将本文件改为当前唯一总计划。
- [x] 更新 README 的阶段状态、文档索引和发布限制。
- [x] 修正保留文档中“Chrome 扩展独立项目”“未来适配器”等旧表述。
- [ ] 每个验证单在实际执行前更新提交号、版本、环境和已失效步骤。

完成条件：所有保留文档对 Chrome 路线、当前状态和完成定义没有冲突。

### 批次 1：对话发送与终态事务

目标：一次发送有唯一身份、单向状态和确定终态。

- [x] 增加 `clientMessageId`、`generationId` 和单调 `revision`。
- [x] Renderer 在 IPC 前进入 `submitting`，同一请求幂等，禁止重复回车插入两条消息。
- [x] 所有回复路径先建立 assistant/generation shell。
- [x] 初始化失败、模型失败、用户取消、任务替换、窗口关闭和应用崩溃分别进入持久 `error`、`cancelled` 或 `interrupted` 终态。
- [x] 启动时恢复遗留 `pending/streaming`，不得显示成完整回答。
- [x] 消息 load 与 stream 按 revision 合并，旧快照不得覆盖新状态。
- [x] 补齐 chat store、消息 IPC 和完整 send → terminal 集成测试。

完成记录（2026-09-23）：本地 JSON 与 MySQL 均保存 generation 元数据并拒绝旧 revision；应用退出等待取消终态落库；自动化覆盖 IPC 幂等、快速终态竞态、重复提交、旧分片、取消和重启恢复。

完成条件：快速回复、连续提交、失败、停止、切换会话和重启均不会卡在生成中或产生假完成消息。

### 批次 2：跨轮上下文、会话隔离和存储

目标：所有对话输入和证据都能按来源恢复，且不会跨会话串用。

- [x] 为用户输入保存 `TurnEnvelope`，记录正文、图片/文档引用与结构化选择；工具证据仍按 generation 保存在助手 block 中。
- [x] 修复文档注入被当前请求覆盖的问题；后续提问可从已保存文档选择有来源的段落。
- [x] 历史回放包含有界 `toolContext`，失败推测与已验证证据分离。
- [x] 建立历史图片明确引用策略：历史仅保留来源说明，本轮看图须重新提供像素。
- [x] 草稿、附件、异步文件任务、滚动和补充提问按 session 隔离。
- [x] 历史裁剪按完整 turn 和连续后缀执行；被裁剪部分只提供带来源 ID 的存在性摘要，不伪称重新读取。
- [x] 使用 SQLite 保存 session/message/generation/block 元数据；旧 JSON 一次性导入并保留原文件。
- [x] 图片和大文档进入 Artifact Store；保存 hash、MIME、大小、来源和生命周期，不把 Base64 写入整库 JSON。
- [x] 增加分页、配额、孤儿清理和删除级联测试。

实现记录（2026-09-23）：按账号隔离的 SQLite 与内容寻址 Artifact Store 已接入；旧 JSON 导入、文档跨轮/重启读取、10,000 条消息分页、附件共享与清理均有自动化测试。历史图片只显示来源，不自动把旧像素再次发给模型；如需分析同一张图，用户需重新上传。真实模型与安装包回归仍属于批次 7。

完成条件：文档与有界工具证据在第二问及重启后可追溯；历史图片可查看，但只有本轮重新提供像素才可再分析；10,000 条消息和多张截图不会拖慢整库写入。

### 批次 3：统一模型驱动能力循环

目标：模型决定是否调用能力，宿主只决定能力是否可用、是否获批以及如何执行。

- [ ] 将普通聊天和 Agent 收敛为同一可选原生工具循环。
- [x] 普通聊天不默认联网；用户本轮结构化选择后才使用厂商搜索。
- [ ] 模型可通过原生工具自行激活搜索，不需要用户每次手动选择。
- [ ] Coding 保留“先观察项目”的独立规则，但不得套到普通聊天。
- [ ] 图片输入可与项目、Skill、插件和 Chrome 能力组合。
- [ ] Renderer 提交结构化 `pluginIds`；多插件选择与任务快照一致。
- [ ] Skill 记录 explicit/automatic 来源，自动匹配不得被描述为用户显式激活。
- [ ] 不支持原生 function calling 的模型不注册需要工具的能力，也不伪造结果。
- [ ] 删除 `prefersBrowserTools()`、`prefersBrowserContinuation()` 对任务创建的决定权。
- [ ] 回归普通问答零联网、图片与项目/插件/Chrome 组合、正则未命中时模型仍可激活浏览器。

完成条件：普通问答零 search、零 MCP、零 workspace 工具；模型调用激活工具后才能展开对应能力目录。

### 批次 4：Google 官方 Chrome DevTools MCP

目标：严格按固定版本 Google 官方 MCP 契约完成自然对话触发、可信页面绑定和连续调用。

详细任务以 `docs/superpowers/plans/2026-09-22-explicit-chrome-context.md` 为准，顺序不得跳过：

1. 保存 `chrome-devtools-mcp@1.7.0` 实际 `tools/list` schema fixture 和映射表。
2. 实现宿主 `browser.activate`；注册它本身不得启动 MCP 或读取页面。
3. 激活后按 purpose 逐轮生成最小工具目录。
4. 主进程建立 `bindingId + mcpGeneration` 可信页面绑定。
5. 一个普通页面自动绑定，多个页面在当前对话内消歧。
6. 规范化 URL 并复用已有页；`new_page` 成功后等待超时不得再次打开。
7. 截图执行“验证绑定 → 等待稳定 → 最新 snapshot → 官方 `take_screenshot`”，页面截图固定 `fullPage: false`。
8. 图片先原子持久化，再按真实 tool call 顺序插入消息；支持折叠、预览、缩放和重启恢复。
9. 回复完成、失败、取消、窗口关闭和任务替换都释放 lease、审批、等待和 MCP 子进程。
10. 完成真实 Chrome 首次调用、连续调用、重连、拒绝、滚动后截图和进程清理验收。

禁止事项：

- 不开发 Chrome 扩展、Native Messaging Host 或私有 CDP 协议。
- 不根据用户正文关键词直接连接 Chrome。
- 不把 Google MCP 的 `selected` 描述成用户肉眼正在看的前台标签页。
- 不猜测官方 schema、UID 或未提供的 CSS/tag 映射。
- 不自动重放结果未知的写操作。

完成条件：`docs/verification/M16-Google-Chrome-DevTools-MCP验证测试单.md` 全部必测项留下真实证据。

## 5. Remote 认证发布轨

默认 `local` 桌面版不依赖认证服务器，应先按上述批次完成。Remote 账号版单独执行 `docs/18-账号认证与登录设计.md` 与 `docs/19-账号认证实施任务拆解.md`：

- 真实腾讯云短信；
- 已审核 QQ/微信网站应用和回调；
- 公开 HTTPS 部署；
- 真实 MySQL、账号绑定、撤销和跨账号隔离；
- 登录、隐私和数据留存页面验证。

除非产品明确规定首个发布版本必须登录，否则这些外部资质不阻塞 local 桌面版发布；Remote 构建不得在外部条件缺失时宣称正式交付。

## 6. 停线条件

出现以下任一情况时停止进入下一批：

- 同一发送可能产生多个 generation，或任一路径没有持久终态。
- 会话切换会串附件、草稿、审批、页面绑定或项目权限。
- 文档、图片、网页或插件内容能够扩大工具目录或绕过 Policy Engine。
- Chrome 工具映射没有对应固定版本官方 schema 和失败测试。
- 截图只存在进程内、重启丢失，或写入失败后仍作为成功展示。
- 真实模型/Chrome 未验收却把相应里程碑标为完成。
