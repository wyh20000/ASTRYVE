# 11 · 全应用视觉系统升级设计

> 状态：设计稿（待用户确认后进入实现）  
> 范围：整个桌面应用，包括标题栏、会话侧栏、对话区、输入区、工作区、设置页、弹窗、浮层与状态栏  
> 核心约束：只重构视觉与展示组件，不改变任何现有业务逻辑、数据结构、IPC 权限或 Agent 行为

---

## 1. 背景与已确认决策

当前界面已具备完整的 Electron + React + Tailwind 页面框架，也已安装 Ant Design 6，但视觉层仍存在以下问题：

- 字号分散且整体偏小。渲染端目前存在大量 `9px`～`13px` 文本，其中 `10px`、`11px`、`12px` 三档使用最密集。
- 原生 `button`、`input`、`textarea` 和自制浮层分散在各业务组件中，交互态、尺寸、圆角和焦点样式不统一。
- Ant Design 只在应用根节点提供了少量颜色令牌，尚未形成全局组件规范。
- 当前主题是“多套预设 + 三项颜色覆盖”，默认固定为午夜蓝，尚未真正跟随操作系统主题。
- 对话、会话列表、附件、思考过程和输入区均为自制展示层，能够工作，但缺少统一的 AI 产品交互语言。

本轮需求已确认：

1. **覆盖整个应用**，不是只优化主对话页面。
2. 字号采用接近 Codex 的分层：正文与控件 `14px`，重要内容与分区标题 `16px`，页面主标题 `20px`～`24px`。
3. 字体优先使用 **Microsoft YaHei / 微软雅黑**，并为非 Windows 平台保留系统字体回退。
4. 主题默认**跟随系统**，同时允许手动选择浅色或深色，并支持自定义主题色与强调色。
5. 可以采用 Ant Design 与 Ant Design X，但库组件只替换展示层；现有 store、IPC、事件订阅、发送链路和工具执行逻辑保持原样。

## 2. 设计目标

### 2.1 体验目标

- 信息密度接近 Codex 桌面客户端：清晰、克制、低噪声，不追求大卡片或过度装饰。
- 默认深色界面采用中性冷灰，而不是当前偏蓝黑的高饱和底色；浅色界面保持相同层级关系。
- 所有常用控件在高度、字号、圆角、边框、hover、active、focus、disabled 和 loading 状态上保持一致。
- 对话区强化内容可读性，用户消息与 Agent 输出层级明确，工具调用和思考过程易于扫描。
- 左侧会话区具备稳定的选中态、分组、搜索、上下文操作和窄宽度表现。
- 设置页、工作区和弹窗与主对话区域属于同一套视觉系统，不再像不同页面拼接而成。

### 2.2 工程目标

- 建立单一设计令牌源，并同步驱动 CSS 变量、Tailwind、Ant Design 和 Ant Design X。
- 建立 `components/ui` 全局组件层，业务页面不再自行拼装通用按钮、输入框和浮层。
- 通过适配器把 Ant Design X 接入现有会话和消息模型，不引入第二套聊天状态管理。
- 分阶段迁移，任何阶段都可独立回归和回退。

### 2.3 非目标

- 不重写会话、消息、模型、插件、Skills、审批、附件解析、工作区或终端逻辑。
- 不更换 Zustand，不引入 Ant Design X 的请求层或 `useXChat` 接管现有流式链路。
- 不修改主进程安全边界、preload 白名单、数据库结构或工具权限策略。
- 不在本轮增加账号、云同步、移动端或新的业务功能。
- 不以一比一复刻 Codex 为目标；参考其信息密度、主题结构和交互克制度，保留本产品现有功能布局。

## 3. 总体架构

视觉系统按四层组织：

```text
主题状态与持久化
  └─ 语义设计令牌（颜色 / 字号 / 间距 / 圆角 / 阴影 / 动效）
       ├─ CSS Variables + Tailwind
       ├─ Ant Design ConfigProvider
       └─ Ant Design X XProvider
            └─ 全局 UI 组件封装
                 └─ 业务页面与现有 store / IPC / handlers
```

关键原则：

- 业务组件只表达“是什么”和“发生什么”，不重复定义基础控件外观。
- 主题值只从语义令牌读取，不在页面中散落 HEX、固定阴影或临时字号。
- Ant Design/X 负责成熟的交互和无障碍基元；产品样式由本项目令牌统一覆盖。
- 现有事件处理函数原样传给新展示组件，迁移时不顺带重构业务流程。

## 4. 字体与排版规范

### 4.1 字体栈

界面字体：

```css
font-family: "Microsoft YaHei", "微软雅黑", "PingFang SC",
  "Noto Sans CJK SC", "Segoe UI", sans-serif;
```

代码与终端字体继续使用等宽字体：

```css
font-family: "JetBrains Mono", "Cascadia Code", Consolas, monospace;
```

说明：微软雅黑优先满足当前 Windows 使用体验；PingFang SC 和 Noto Sans CJK SC 用于 macOS/Linux 回退。代码、终端、哈希和路径不强制使用微软雅黑。

### 4.2 字号层级

- `14px / 22px`：正文、按钮、输入框、下拉框、会话项、菜单项、表单标签、辅助说明、时间和状态信息。
- `16px / 24px`：分区标题、重要消息、设置组标题、空状态主文案、对话标题。
- `20px / 28px`：普通页面主标题。
- `24px / 32px`：需要更强识别的设置首页或欢迎页标题，谨慎使用。
- 等宽代码默认 `14px / 21px`；Monaco 编辑器可保留独立可配置字号，但默认调至 `14px`。

迁移完成后，不再出现 `9px`～`13px` 的业务文字。图标内部装饰文字如确有空间限制，也必须优先改布局，而不是继续缩小字号。

### 4.3 字重与可读性

- 正文默认 `400`；按钮、标签和小标题使用 `500`；页面标题使用 `600`。
- 中文正文不使用全大写、过宽字距或过轻字重。
- 单行控件文字不得通过压缩行高解决拥挤；控件最小高度与字号一起调整。
- 正文对背景对比度至少满足 WCAG AA；弱文本不承载关键操作或错误信息。

## 5. 主题系统

### 5.1 模式

主题模式调整为：

- `system`：默认值，实时跟随操作系统浅色/深色变化。
- `light`：固定浅色。
- `dark`：固定深色。

设置页提供“跟随系统 / 浅色 / 深色”分段选择。选择 `system` 时展示当前实际生效模式，但不把它改写为固定模式。

### 5.2 自定义能力

保留并升级以下自定义项：

- 强调色。
- 应用背景色。
- 前景文字色。
- UI 字号基准，默认 `14px`；第一版可只展示并固定为 14，待验证布局稳定后再开放有限范围调节。
- 一键恢复默认。

自定义值建立在当前浅色或深色基线上，由算法派生悬浮层、选中层、边框、弱文本和焦点环；不要求用户逐项配置所有颜色。

### 5.3 语义令牌

颜色令牌扩展为以下语义组：

- Surface：`app`、`sidebar`、`panel`、`raised`、`overlay`、`hover`、`active`。
- Border：`subtle`、`default`、`strong`、`focus`。
- Text：`primary`、`secondary`、`muted`、`inverse`、`link`。
- Accent：`primary`、`hover`、`active`、`soft`、`contrastText`。
- Status：`success`、`warning`、`error`、`info` 及各自 soft 背景。
- Code：编辑器、行内代码、代码块、diff 增删背景。

深色默认建议使用近似 Codex 的中性冷灰层级，例如应用背景约 `#111315`、侧栏约 `#181B1E`、浮层约 `#202428`；最终色值需在真实 Electron 窗口中依据对比度和显示效果校准，而不是直接复制截图取色。

### 5.4 持久化与兼容

当前 `PersistedTheme` 只有 `presetId + overrides`。实现时升级为带版本的设置结构，至少包含 `mode`、`overrides` 和可选 `uiFontSize`。

- 新安装默认 `mode: system`。
- 已有用户的 `midnight/obsidian/forest/amber` 映射为 `dark` 并保留强调色；`daylight` 映射为 `light`。
- 读取旧设置时即时迁移，写回新结构；迁移失败时使用系统主题，不影响应用启动。
- 系统主题变化只更新实际主题，不覆盖用户保存的 `system` 选择。
- Electron 标题栏 overlay 与页面主题同步更新。

## 6. 全局组件层

在 `src/renderer/src/components/ui` 建立项目自己的组件 API。业务代码优先引用这些封装，而不是直接散用原生控件或库组件。

首批组件：

- `Button`：`primary`、`default`、`text`、`danger` 四种语义；支持 loading、disabled、图标与危险操作。
- `IconButton`：统一 32px/36px 点击区域、Tooltip、焦点态和 aria-label。
- `Input`、`TextArea`、`SearchInput`：统一高度、清空按钮、错误/禁用状态。
- `Select`、`DropdownMenu`、`ContextMenu`：基于 Ant Design Select/Dropdown，统一弹层容器与键盘导航。
- `Tabs`、`Segmented`：用于工作区、设置页和主题模式。
- `Tooltip`、`Popover`：统一延迟、宽度、阴影和浮层层级。
- `Modal`、`Drawer`、`ConfirmDialog`：统一标题、按钮顺序、危险操作和焦点管理。
- `Checkbox`、`Radio`、`Switch`、`Slider`、`ColorPicker`。
- `Tag`、`Badge`、`StatusDot`、`EmptyState`、`Spinner`、`Skeleton`。
- `FormSection`、`SettingRow`：消除设置页中重复的标题、说明和右侧控件布局。

封装策略：

- 不二次复制 Ant Design 的完整 API，只暴露本项目真正需要的语义属性。
- 业务事件参数尽量保持当前形式，避免迁移时连带修改 store。
- 基础尺寸和视觉全部从令牌读取；特殊页面可通过 `className` 微调布局，但不能重新定义控件状态色。
- 原生文件选择 input 可继续隐藏存在，由封装按钮触发，不改变附件逻辑。

## 7. Ant Design X 接入方案

Ant Design X 官方提供 `Bubble`、`Sender`、`Conversations`、`Attachments`、`Actions`、`Welcome`、`Think/ThoughtChain` 和 `XProvider` 等 AI 场景组件。本项目只采用其展示组件和交互基元，不采用它的网络请求或聊天状态方案。

官方参考：

- [Ant Design X 组件总览](https://x.ant.design/components/overview/)
- [Bubble](https://x.ant.design/components/bubble/)
- [Sender](https://x.ant.design/components/sender/)
- [Conversations](https://x.ant.design/components/conversations/)
- [XProvider](https://x.ant.design/components/x-provider/)

### 7.1 Provider

根节点由单一主题对象同时配置 Ant Design 和 Ant Design X。优先使用 `XProvider` 承接 Ant Design 的能力，避免嵌套两个相互漂移的主题源。中文 locale、圆角、字号、颜色和组件级 token 在此集中设置。

### 7.2 消息列表

`MessageList` 的滚动容器、置底判断和 ResizeObserver 逻辑保留；内部列表迁移至 `Bubble.List` 或逐项 `Bubble`：

- 用户消息使用 `placement="end"`，保留附件预览、复制和时间。
- Agent 消息使用 `placement="start"` 与 `borderless`，内容继续由现有 `Blocks`、`RichText`、`MarkdownRenderer` 渲染。
- streaming、error、thinking 和 tool block 状态继续来自现有 `Message` 数据。
- `Bubble` 只控制消息布局、插槽和统一间距，不改变消息模型。
- “回到底部”逻辑继续由当前组件控制，避免库内部滚动与现有滚动状态冲突。

### 7.3 输入区

`ChatInput` 迁移至受控 `Sender`，但保留所有现有能力：

- 发送、停止生成、Enter/Shift+Enter 规则。
- 输入历史、粘贴图片、拖拽文件、文件选择与解析状态。
- `/Skill` 菜单、`@插件` 菜单及其键盘选择。
- 模型选择、推理等级、项目/Agent 控制。
- 用户补充问题卡片和审批流程。

附件区域优先采用 `Attachments`/`FileCard` 的布局能力；若其数据结构无法覆盖当前解析状态，则在 `Sender.Header` 中继续渲染现有附件卡片，统一视觉即可，不为使用组件库而损失功能。

### 7.4 会话侧栏

会话列表迁移到 `Conversations`：

- `items` 由现有 `sessionStore.sessions` 映射生成。
- `activeKey` 继续绑定 `sessionStore.activeId`。
- `onActiveChange` 继续调用当前 `select`。
- 分组继续使用今天、昨天、更早，不改变现有时间归类逻辑。
- 删除操作放入行尾菜单或悬浮操作，仍执行当前二次确认和 `remove`。
- 搜索继续由 `uiStore.searchQuery` 驱动，不把搜索状态迁入组件内部。

### 7.5 思考、工具与结构化内容

- 思考过程可用 `Think` 或 `ThoughtChain` 表达，但底层数据仍来自当前 block。
- 文件、来源和操作动作可逐步采用 `FileCard`、`Sources`、`Actions`。
- 复杂工具时间线和审批卡片若与 X 组件语义不一致，继续使用项目组件，只同步 token 和排版。
- Markdown 首轮保留现有渲染器，避免链接、代码高亮和自定义 block 行为同时发生变化；是否迁移到 X Markdown 另立任务评估。

## 8. 分区域视觉方案

### 8.1 窗口与标题栏

- 标题栏高度和点击区域统一，按钮图标使用相同线宽。
- 拖拽区域与交互按钮明确分离，不能因样式重构破坏窗口拖拽或系统按钮。
- 标题栏、侧栏与主内容通过轻微明度差区分，不使用粗重边框。

### 8.2 左侧会话管理

- 默认宽度建议 260px，可拖拽范围保持现有逻辑并重新校准最小宽度。
- Logo、应用名、新对话、搜索、分组列表和底部设置形成稳定的纵向节奏。
- 会话行目标高度 40px～44px；选中态使用浅背景 + 细强调标记，不使用高饱和整块填充。
- 时间和操作图标保持 14px，但通过颜色弱化，不通过缩成 10px 弱化。
- 折叠态保留常用入口，并提供 Tooltip；不新增业务操作。

### 8.3 对话主区

- 内容最大宽度由当前 820px 调整至约 860px～920px，并根据窗口宽度自适应。
- Agent 回复以无边框内容流为主；用户消息使用轻量圆角背景，避免两侧都成为厚重气泡。
- 消息间距使用固定节奏，结构化工具块内部密度略高于正文。
- Markdown 正文 `14px / 1.65`，标题从 16px 起；代码块 `14px / 1.5`。
- 用户消息复制、Agent Actions、时间等操作在 hover 或键盘 focus 时可见，同时保证触屏/无 hover 环境可访问。

### 8.4 输入区

- 输入框采用 Codex 风格的低对比描边与中等圆角，不使用过强阴影。
- 默认最小高度约 96px，随输入增长，最大高度保持当前约束。
- 附件、模型、推理等级、发送/停止动作具有稳定位置；窄宽度时允许工具区折叠，而不是缩小字体。
- 发送按钮、停止按钮共享同一尺寸和交互反馈。
- “AI 生成内容可能不准确”保留，字号调整为 14px，并降低颜色权重。

### 8.5 右侧工作区

- 工作区 Tabs、文件树、编辑器标签、终端和状态条统一采用全局组件及令牌。
- 文件树和终端不再依赖 10px～11px 字号；默认 14px，通过行高和横向滚动解决密度问题。
- Monaco 自身主题由新主题对象生成或映射；编辑器业务与文件读写逻辑不变。
- 终端输出保持等宽字体，可选中区域和键盘输入行为不变。

### 8.6 设置页

- 左侧设置导航、搜索和内容区重做为 Codex 式双栏设置布局。
- 表单统一使用 `SettingRow`：左侧名称与说明，右侧控件；窄窗口改为上下排列。
- “外观”页提供系统/浅色/深色模式、主题预览、自定义色和恢复默认。
- 插件、技能、模型、Agent、数据库等页面只迁移控件和排版，不改变安装、保存、测试、审批或连接逻辑。

### 8.7 弹窗、浮层与反馈

- ApprovalDialog、插件详情、删除确认和错误提示统一 Modal/Popover 规范。
- 危险操作使用明确的 danger 语义，不只依赖红色文字。
- Toast、Message、Tooltip 的颜色和字体由全局 Provider 控制。
- 所有浮层 z-index、阴影和背景归入统一令牌，避免互相遮挡。

## 9. 响应式与窗口约束

本产品以桌面端为主，但必须覆盖常规窗口与窄窗口：

- 宽窗口：完整三栏布局。
- 中等窗口：工作区可折叠，侧栏保持可用宽度。
- 窄窗口：优先保证对话输入和主要内容，侧栏/工作区通过现有开关收起；设置表单改为纵向。
- 不通过把文字缩小到 14px 以下适配窄窗口。
- 长模型名、路径、会话名和插件名采用省略 + Tooltip；关键错误信息允许换行。
- 任何弹窗不得超出可视区域，长内容内部滚动。

建议在实现前冻结人工验收尺寸：`1280×800`、`1440×900`、`1920×1080`，并增加当前应用允许的最窄窗口尺寸。

## 10. 不破坏逻辑的迁移约束

以下行为必须在改造前后保持一致：

- 会话的新建、选择、搜索、删除、分组和持久化。
- 消息加载、流式更新、自动滚动、停止生成、错误态和恢复。
- 输入历史、快捷键、附件粘贴/拖拽/选择、文档解析、Skill 和插件 mention。
- 模型选择、推理等级、工作区选择、Agent 设置和发送参数。
- 工具时间线、审批范围、用户补充问题、插件权限与审计。
- 工作区面板切换、文件树、Monaco、diff、终端和刷新行为。
- 设置页所有保存、测试、安装、更新、启停和卸载动作。
- Electron 窗口拖拽、标题栏按钮、侧栏和工作区 resize。

实施规则：

1. 先为关键交互补足行为测试或记录基线，再替换展示组件。
2. 每次只迁移一个组件族，不在同一变更中重写 store 或 IPC。
3. 新组件通过 adapter 接收现有数据并调用现有 handler。
4. 发现组件库 API 无法无损表达现有功能时，保留现有组件并仅统一样式。
5. 不删除旧样式，直到对应区域通过自动化与人工回归。

## 13. 风险与应对

- **Ant Design 6 与 Ant Design X 版本兼容**：实现前核对并锁定版本，先做最小原型和生产构建，不直接全量迁移。
- **组件库默认样式压过产品主题**：只通过 Provider token、组件 token 和语义 class 覆盖，避免全局高优先级 CSS 对抗。
- **Sender 无法覆盖复杂输入能力**：以受控 adapter 接入；必要时使用 Sender 插槽承载现有附件、模型和 mention UI。
- **Conversations 无法完整表达现有分组/确认**：保留现有分组计算和确认状态，使用自定义 label/menu 渲染；无法无损时保留列表逻辑。
- **字体增大造成布局溢出**：调整行高、控件高度和容器宽度，不回退到小字号；对长内容使用换行、省略和 Tooltip。
- **系统主题首帧闪烁**：在 React 挂载前读取系统偏好并应用基础变量，hydrate 后再合并持久化设置。
- **范围过大导致回归难定位**：按组件族拆分，每阶段保留可运行状态和独立验证记录。

## 14. 实现前仍需冻结的细节

以下细节不阻塞本设计，但应在对应阶段开始前以真实页面原型确认：

- 深色与浅色默认色板的最终色值。
- 强调色默认值；建议先用克制的蓝色，避免参考图中的粉色成为产品默认。
- 会话侧栏默认宽度和允许的最窄窗口尺寸。
- 用户消息气泡最大宽度、对话内容最大宽度和输入框默认高度。
- 是否在第一版开放 UI 字号调节，还是先固定 14px 完成全应用迁移。

这些属于视觉校准，不允许改变本文已冻结的逻辑保护边界。
