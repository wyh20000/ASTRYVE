# 插件页面优化设计

## 1. 文档目的

本设计把插件设置页对齐 Codex 的插件浏览体验，同时保留当前插件运行时、安装安全校验、MCP 连接、插件启停、卸载、备份回滚、自动更新和任务快照行为。

本轮只修改渲染层页面结构、详情导航和必要的只读技能展示接缝；不改变插件包格式、市场源安全策略或 Agent 工具注册规则。

## 2. 已确认的产品决策

1. “已安装”区只展示已经下载到本机的插件图标，不展示描述卡片。
2. 市场中的未安装插件右侧显示“安装”，点击后直接安装，并显示处理中状态。
3. 已安装插件在市场分组中显示 `...` 菜单，保留“立即试用 / 管理 / 卸载”三项。
4. 点击插件、管理或详情入口，进入同页全屏详情页；详情页提供返回插件列表，不再使用当前右侧详情抽屉。
5. “立即试用”关闭设置、创建或复用空会话，并在输入框预填 `@插件ID `，不自动发送。
6. 插件详情展示插件包含的技能；每个技能使用独立二态开关。这里采用 switch，而不是 radio：技能之间不是互斥选项。
7. 市场分组使用固定产品分类：`Featured`、`Productivity`、`Creativity`、`Developer Tools`、`Data & Analytics`、`Communication`、`Education & Research`、`Scientific Research`、`Security`、`Finance`。分组依据必须来自市场条目的 `categories` / `recommended` 字段，不能凭名称猜测或伪造运营数据。

## 3. 当前代码边界

现有实现已经提供以下不可回归的能力：

- `filterMarketplaceEntries`、`latestMarketplaceEntries` 和 `describePluginInstallRisk` 负责市场筛选与安装/更新风险判断。
- `PluginMarketplaceDetails` 当前是右侧抽屉，包含权限、来源、签名、兼容性、数据目标、SHA-256 和更新风险。
- `PluginRow` 已提供插件启停、受管插件限制、卸载、历史版本和 MCP 连接入口。
- `PluginMetadata.components` 能判断插件是否声明 `skills`；插件技能通过 `SkillMetadata.pluginId` 关联。
- `useSkillStore.setEnabled` 已有技能启停 IPC，不需要另造一套持久化状态。
- `useUiStore.pendingPrompt` 与 `ChatInput` 已支持从设置页跳转新对话并预填文本。
- 已安装插件在任务创建时被快照化；页面上的安装、启停或技能切换不能静默改变正在运行任务的工具集合。

## 4. 页面结构

### 4.1 插件列表页

页面保持“插件 / 技能”顶层标签和现有设置入口。插件标签页内部调整为：

```text
插件
在你常用的工具中与 AI Agent 协作                         添加
搜索插件

已安装                                      设置/自动更新入口
[图标] [图标] [图标] ...

固定分类分组（Featured / Productivity / …）

Featured
  插件行                                             ... / 安装

Productivity
  插件行                                             ... / 安装
...
```

“已安装”图标区：

- 仅渲染 `usePluginStore.items` 中已下载的插件。
- 图标优先使用市场条目的 `logoDarkUrl` / `logoUrl` / `composerIconUrl`，没有市场映射时使用现有占位图标。
- 图标按钮必须有 `aria-label="打开 <插件名>"` 和 tooltip；无图标资源时仍保留稳定尺寸，避免布局跳动。
- 图标点击打开该插件的详情页。
- 插件数量较多时换行，不引入横向滚动；每个图标容器使用固定尺寸。
- 原有自动更新偏好保留在已安装区右侧或列表页工具菜单中。

市场区：

- 继续支持搜索、来源范围和市场源同步状态。
- 安装状态由 `describePluginInstallRisk` 决定，不能仅凭 `items.includes(id)` 判断。
- `install` 状态显示“安装”；点击后调用现有 `installMarket`，仅当前 `sourceId + pluginId` 对应按钮进入 loading/disabled，其他插件仍可安装；成功后刷新已安装图标和市场操作菜单。
- `update` 状态仍显示“更新”，需要保留现有详情风险确认流程；不能把有新增权限、来源变化或发布者变化的更新改成无确认直装。
- `older` 状态保持禁用或进入详情说明，不允许降级直装。
- `installed` 状态显示三点菜单，不显示重复安装按钮。
- `installable === false` 继续显示“待支持”，不可操作。

### 4.2 已安装插件三点菜单

菜单项固定为：

1. **立即试用**：关闭设置、复用或新建空会话、预填 `@<plugin.id> `。
2. **管理**：打开该插件的全屏详情页。
3. **卸载**：沿用现有卸载确认与 `keep / clear` 数据保留分支；受管插件不显示卸载。

历史版本、回滚、MCP 连接和重新授权属于“管理”详情页中的能力，不删除现有入口。三点菜单打开时要使用 `useDismissibleLayer`，点击外部或 Escape 关闭，并把焦点回退到触发按钮。

### 4.3 全屏插件详情页

详情页在设置内容区域内替换列表，不新开窗口，不改变 `settingsOpen`。顶部提供：

- 面包屑：`插件 > <插件名>`。
- 返回按钮，返回插件列表并恢复列表搜索/分组状态。
- 插件图标、名称、版本、作者、来源、验证状态和描述。
- 右上角操作：未安装为“安装插件”；已安装为三点菜单或主要操作按钮。

详情内容按以下顺序排列：

1. **推荐提示区**：市场条目提供可用时展示推荐提示/示例 prompt；没有真实字段时不生成占位文案。
2. **技能**：展示该插件关联的技能数量和技能行。每行显示技能图标/占位、显示名称、描述和独立 switch。开关使用 `role="switch"`、`aria-checked` 和 `aria-label="启用/禁用 <技能名>"`。
3. **连接与运行状态**：复用现有 MCP `pending / connected / failed / restricted` 状态、连接、重授权、重试、断开和共享连接提示。
4. **权限与数据**：保留现有权限中文标签、能力、数据目标、兼容性、来源和签名信息。
5. **版本管理**：保留更新风险、历史版本、备份和回滚；受管插件仍只能禁用，不能卸载。
6. **危险操作**：卸载按钮沿用现有 `PluginUninstallChoices`，明确“保留数据 / 清除数据”两条路径。

详情页必须保留错误、隔离和无效清单诊断；无效插件仍可查看诊断，但不能显示可用的技能开关或试用入口。

## 5. 技能展示与启停契约

### 5.1 数据来源

优先复用 `useSkillStore.load(workspaceId)` 返回的 `SkillMetadata[]`，按 `skill.pluginId === plugin.id` 过滤。插件技能已由 Skill Registry 从插件 `skills` 路径发现，并带有 `pluginId`。

详情页进入时加载一次技能列表；插件启用状态变化、安装完成、卸载或恢复后重新加载，避免显示过期状态。

### 5.2 禁用插件时的显示

当前 Skill Registry 对禁用插件不会把其技能加入可用技能列表。为保持详情页可解释性：

- 已安装且插件启用：显示真实技能和独立开关。
- 已安装但插件禁用：通过只读的插件技能清单 IPC 展示真实技能名称和描述；技能 switch 保持禁用，直至插件启用。该 IPC 仅解析插件目录内 `SKILL.md` frontmatter，不注册技能、不执行正文。
- 未安装市场插件：详情页只展示市场清单中真实存在的组件信息；安装完成后再展示本机已解析技能。

技能开关调用既有 `skills.setEnabled({ id, enabled, workspaceId })`。开关 pending 时只锁定该行，失败保留原状态并显示错误；不影响插件级启停。

## 6. 立即试用流程

```text
点击立即试用
  -> sessionStore.create()（复用空会话，否则新建）
  -> setPendingPrompt({ text: `@${plugin.id} `, sessionId })
  -> closeSettings()
  -> 目标会话的 ChatInput 同步并一次性消费 pendingPrompt
  -> 用户确认后按 Enter 发送
```

预填内容绑定到目标会话，旧会话输入框不会收到内容；消费后即使删除目标会话或重新进入设置页，也不会再次出现。

发送时仍由现有 `pluginConversation` 从 `@插件ID` 解析显式插件选择，主进程重新校验插件是否已安装、启用、可用。页面不得直接把未经校验的插件对象注入任务工具目录。

## 7. 市场分组规则

市场源数据需要逐步统一到以下分类值：

| 展示分组 | 真实数据规则 |
| --- | --- |
| Featured | `recommended === true`；没有该字段时不进入 Featured |
| 其他固定分类 | `categories` 包含对应分类名 |
| 未分类 | 无匹配分类时进入 `Other`，不丢弃条目 |

分类名建议在索引层规范化为英文 canonical 值，同时在 UI 层通过字典显示中文或英文产品文案。`Scientific Research` 使用正确拼写；兼容历史索引中的 `Scientfic Research` 时在解析阶段归一化，不在渲染层写特殊分支。

同一插件属于多个分类时只在首个匹配分类显示，避免重复卡片；搜索有结果时仍可切换为扁平“搜索结果”视图，保证查找效率。

## 8. 插件源如何维护

### 8.1 用户维护入口

进入：`设置 > 插件 > 市场源`。

当前仓库已有维护能力：

- 添加 HTTPS 市场索引 URL 和名称。
- 可选填写签名密钥 ID 与 Ed25519 公钥。
- 手动同步。
- 启用/禁用社区或 GitHub 源。
- 删除非官方源。
- 查看上次同步时间和错误信息。

内置 Codex 官方源由应用维护，不能删除或禁用。市场源配置和已同步条目持久化在用户数据目录的 `plugin-market.json`，不应由渲染层直接写文件。

### 8.2 市场索引维护建议

自建源发布一个 HTTPS JSON 索引，条目至少包含：`id`、`name`、`version`、`description`、`author`、`packageUrl`、`sha256`、`permissions`、`categories`、`components`、`platforms`、`architectures`。每个版本使用不可变下载地址和固定 SHA-256；有签名时同时提供签名和签名密钥标识。

分类应使用本设计第 7 节的 canonical 值。索引发布新版本后用户在市场源页点击“同步”；同步失败保留旧条目并展示错误，不清空可用市场。

### 8.3 安全边界

- 仅允许 HTTPS；索引大小、条目数量、版本格式、路径穿越、包摘要和签名继续由主进程校验。
- 社区源默认未验证；不能通过 `verified` 字段伪装官方来源。
- 新增权限、来源变化或发布者变化的更新必须重新确认。
- 关闭市场源会移除该源的市场条目，但不卸载已经安装的插件。

## 9. 需要新增/调整的实现点

### 渲染层

- 将 `PluginMarketDetails` 从抽屉改为 `PluginDetailsPage`，增加列表/详情视图状态和返回处理。
- 新增已安装图标条和插件三点菜单；抽取共享的 `PluginActionMenu`。
- 安装按钮使用按 `sourceId + pluginId` 区分的 pending map，独立显示 loading，避免全页面按钮误锁定。
- 市场卡片按固定分类字典分组，保留现有过滤和风险判断函数。
- 详情页加载并过滤 `SkillMetadata.pluginId`，接入既有 `useSkillStore.setEnabled`。
- 立即试用先创建/复用目标空会话，再写入带 `sessionId` 的一次性 `pendingPrompt`，避免污染旧会话。

### 共享类型/主进程（仅在确有需要时）

- 禁用插件详情通过只读 `plugins.listSkills({ id })` IPC 显示技能；该 IPC 只能返回 frontmatter 元数据，不能执行 Skill 正文。
- 若市场索引已有分类别名，优先在 `pluginMarketplace` 解析时归一化，不修改运行时插件权限和工具注册。

## 10. 验收清单

1. 已安装区只显示本机已下载插件图标；未安装插件不会出现在这里。
2. 未安装市场插件点击“安装”有 loading，安装成功后图标区和市场状态同步更新。
3. 已安装市场插件显示三点菜单，菜单包含立即试用、管理、卸载；受管插件无卸载。
4. 点击图标、市场卡片或管理进入全屏详情；返回后搜索、分组和滚动状态不发生异常丢失。
5. 详情页技能行显示开关；启停调用现有 Skill IPC，失败可恢复，不能改变其他技能状态。
6. 点击立即试用后进入新/空对话，输入框出现 `@插件ID `，不自动发送；发送时仍走主进程显式插件校验。
7. MCP、启用/禁用、更新风险、历史版本、回滚、卸载保留/清除、隔离恢复和自动更新回归通过。
8. Featured 与 9 个固定分类分组可展示；`Scientfic Research` 兼容归一化为 `Scientific Research`。
9. 市场源可添加、同步、禁用、删除；官方源不可删除/禁用；同步失败保留旧缓存。
10. 键盘可达性：菜单、详情返回、技能 switch、安装按钮和卸载确认均有可访问名称、焦点回退和 Escape 行为。

## 11. 测试计划

- 保留并运行现有 `SettingsPage`、市场筛选、风险判断、插件 Store、技能 Store、插件运行时和 MCP 测试。
- 新增页面测试：已安装图标、市场直装 loading、三点菜单、详情全屏返回、`@plugin.id` 预填、技能开关和分类分组。
- 新增源维护测试：官方源保护、自定义源同步失败保留旧缓存、分类别名归一化。
- 运行 `npm test`、`npm run typecheck`、`npm run build`；最后使用真实 Electron 窗口在常规宽度和窄宽度复核详情页与菜单不遮挡。
