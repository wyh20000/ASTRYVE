# 插件/技能页对齐 Codex —— 改造约束清单

> 用途：这是一次「还原度优先，但逻辑不能错」的布局改造。
> 现有 **44+ 测试**锁定了行为与结构契约，本文件记录哪些能改、哪些不能动，
> 避免为了还原度悄悄破坏已承诺的行为。

## 一、绝对不可动的逻辑（红线）

| 领域 | 不可动的内容 | 原因 |
| --- | --- | --- |
| 市场筛选 | `filterMarketplaceEntries`、`latestMarketplaceEntries` | 被测试直接调用；同时决定范围筛选与能力搜索 |
| 安装风险 | `describePluginInstallRisk` 的 install / update / older / installed 四种模式 | 决定了权限/发布者变化提示与按钮文案 |
| 详情抽屉 | `pending` + `opener` 焦点回退、`trapPluginDialogFocus` | 键盘可达性契约（有独立测试） |
| 卸载 | `PluginUninstallChoices` 的 keep / clear 三分支 | 有独立测试断言三种选择 |
| MCP | 连接 / 重授权 / 重试 / 断开的 pending、failed、restricted 状态 | 有独立测试 |
| 自动更新 | `preferences.autoUpdate` 偏好与受管插件的可禁用不可卸载 | 有独立测试 |
| 数据源 | 官方源 URL、SHA 固定、清单解析路径 | 刚修好的同步链路 |

## 二、测试锁定的呈现契约（改布局必须满足）

### 技能页
- 描述文字**必须保持可见**（`审查项目代码` 在折叠态就能看到）
- 以下内容**必须只在展开后出现**：
  - `声明 1 个工具，仍受权限审批`
  - `references/checklist.md`
  - `已被高优先级同名项覆盖`
  - `Skill frontmatter 未闭合`
- 启用开关必须是 `role="switch"` + `aria-checked`，
  且带 `aria-label="禁用 <名称>"`

### 插件页
- 已安装行必须包含：名称、描述、版本号、权限中文标签、来源名称
- 启用态是标准开关语义（`role="switch"`）
- 非受管插件必须有可访问的**卸载**与**历史版本**入口
- 无效清单渲染为禁用的诊断行
- 市场卡片必须提供 `aria-label="查看 <名称> 详情"`
- 范围筛选按钮用 `aria-pressed`

### 技能详情弹窗的范围限制（重要）

Codex 的详情弹窗包含**技能正文**（SKILL.md 的完整指令内容）。
本项目 `SkillMetadata` **不包含正文**：

- `skillRegistry.ts` 确实读取并解析了 SKILL.md（含 frontmatter 校验），
  但只把 `description` 等元数据放进 `SkillMetadata`；
- 正文没有走 IPC，渲染进程拿不到。

因此弹窗**只展示真实存在的字段**（来源、触发方式、工具策略、状态、版本、
仓库、可用工具、资源路径），**不展示占位或编造的正文**。
若后续要还原正文，需要新增 IPC 并限定「只读技能目录 + 大小上限」。

### 「立即试用」的实现

= 新建（或复用空）会话 → 关闭设置 → 预填 `/技能名`。

- 与技能既有的 `/名称` 调用方式一致（界面就提示「输入 `/` 调用」）；
- **刻意不自动发送**，用户仍可确认后再按 Enter；
- 为此在 `uiStore` 增加 `pendingPrompt`，由 `ChatInput` 消费一次后清空，
  避免切换会话时被重复填充。

### 一处需要记住的测试维护经验

把开关从行移入弹窗后，有 4 个测试失败，其中**2 个与开关语义无关**——
「来源筛选」「搜索框」两个用例其实是拿开关当「该行是否存在」的探针。
已改为用行自身的可访问名（`查看技能 X 详情`）作探针，这更贴近用例本意。

另外发现技能 store 的测试 mock 用裸 `vi.fn()`（返回 `undefined`），
与真实契约 `Promise<boolean>` 不符，导致 `.then` 抛未处理错误
（vitest 警告可能掩盖真实失败）。已修正 mock。

## 四、分组数据的诚实边界

Codex 的「热门 / 新品推荐 / Small Business」是**运营分组**。
本项目数据里只有：

- `recommended: boolean`
- `categories: string[]`
- `sourceKind: 'official' | 'community' | 'github'`

因此分组**只用这些字段**（推荐 → 分类 → 其他），
**不虚构**热门排行、下载量或运营位。
`buildMarketGroups` 的 6 条测试固化了这个边界。
