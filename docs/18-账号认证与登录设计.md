# 账号认证与登录设计

## 决策

- 本仓库新增独立部署的认证服务；Electron 客户端不保存短信、QQ 或微信的服务端密钥。
- 首期采用手机号短信验证码，以及 QQ、微信官方授权。首次验证成功即注册账号；已有身份则登录。同一个人跨方式绑定账号需要另行完成已登录态下的明确绑定流程，不能依据昵称或手机号猜测合并。
- 平台资质和密钥尚未申请。未配置的方式明确显示不可用，绝不发放测试码、固定码或伪造身份。
- 旧客户端数据不迁移。新账号使用独立本地数据目录，退出账号后不显示上一个账号的对话、工作区和插件数据。
- 首次启动显示登录页。已有会话必须在线向服务端确认有效后才解锁客户端；失效或无网络时保持锁定。

## 安全边界

1. 服务端是账号与会话的唯一可信来源。短信验证码只在服务端生成、限时、限次数、单次使用，并限制 IP 与手机号发送频率。第三方授权由系统浏览器完成，回调由服务端核对一次性 `state`；客户端不接收平台密钥。
2. 认证服务的业务接口默认要求有效会话。匿名白名单仅包括健康检查、登录启动、短信验证码发送及验证、第三方回调与客户端登录结果查询。每个接口限制请求方法、正文大小、请求速率；错误不透露账号是否存在。
3. Electron 主进程对所有现有业务 IPC 统一检查可信 Renderer 来源和当前已验证会话。登录相关 IPC 单独列白名单。React 登录页只是交互层，不能充当权限边界。
4. 会话凭据只保存在操作系统保护的存储中；渲染进程不读取 token。服务端只保存 token 摘要，支持过期、轮换和主动撤销。退出或切换账号时停止任务、关闭窗口并重新初始化账号数据。
5. 本地按服务端用户 ID 划分数据目录。目录名必须通过严格 UUID 校验，不接受 Renderer 传入的路径。旧全局数据原样留存，不自动关联任何账号。
6. 登录页的 Three.js 动画仅做装饰；支持减少动态效果、GPU 不可用时回退，并限制像素比和帧率。认证表单始终可操作。

## 待完成的外部配置

- 可公开访问的 HTTPS 域名、数据库和反向代理。
- 腾讯云短信签名、模板、应用 ID 与服务端密钥。
- QQ 互联及微信开放平台已审核应用、回调域名、App ID 和服务端密钥。

这些配置齐备前可完成代码、自动化测试和本地联调，但不能声称真实短信或 QQ/微信登录已经验收。

## 验收

- 全新安装只显示登录；无会话调用对话、插件、工作区、设置等 IPC 被拒绝。
- 真实短信和 QQ/微信授权可创建/复用账号；错码、过期码、重放、错误 `state`、伪造回调均失败。
- 切换账号不串读本地数据；退出后无法继续运行旧任务或调用业务接口。
- 会话过期、服务端撤销、网络中断均保持锁定；恢复网络后须重新验证。
- 登录界面在常规和窄窗口可用，动画失效、减少动态效果时仍可完成认证。

安全依据：[OWASP Authentication](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)、[OWASP Session Management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)、[腾讯云短信 Node.js SDK](https://cloud.tencent.com/document/product/382/43197)。
