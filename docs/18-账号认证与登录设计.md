# 账号认证与登录设计

## 决策

- Electron 首次启动只显示客户端锁定页：产品标识、居中的 Sign in 入口及必要的登录中、失败和重试状态。锁定页使用 Three.js 深空粒子场与低亮度波动极光，鼠标附近的粒子排斥后回流；减少动态效果时停止动画，WebGL 不可用时显示静态星云背景。客户端不放手机号输入框、短信验证码或第三方登录表单。
- 点击 Sign in 后由系统默认浏览器打开独立部署的 HTTPS Web 登录页。Web 页延续深空星粒与波动极光背景，居中使用浅透登录卡片；减少动态效果时保持静态背景和可操作表单。手机号短信验证码、QQ 和微信官方授权均在 Web 流程中完成；不使用 Electron 内嵌 WebView 登录。认证服务和 Web 登录页控制身份验证，客户端仅在服务端确认会话后解锁。
- 首次验证成功即注册账号；已有身份则登录。同一个人跨方式绑定账号需要另行完成已登录态下的明确绑定流程，不能依据昵称或手机号猜测合并。
- Electron 客户端不保存短信、QQ 或微信的服务端密钥。平台资质和密钥尚未申请；未配置的方式在 Web 页明确显示不可用，绝不发放测试码、固定码或伪造身份。
- 旧客户端数据不迁移。新账号使用独立本地数据目录，退出账号后不显示上一个账号的对话、工作区和插件数据。
- 已有会话必须在线向服务端确认有效后才解锁客户端；失效或无网络时保持锁定。Web 页显示登录成功不能单独解锁客户端。

## 登录与回到客户端

1. Electron 主进程生成短期、一次性的登录请求、随机 `state` 和 PKCE S256 挑战；只监听随机端口的 `127.0.0.1` 回调，并用系统浏览器打开服务端允许的 HTTPS 登录地址。Renderer 只发起 Sign in，不生成或接收凭据。
2. Web 登录页展示当前可用方式。短信发送及验证由 Web 页调用认证服务；QQ/微信通过各自官方授权页返回服务端。服务端验证身份后，将短期、单次使用且绑定本次请求与 PKCE 挑战的授权码重定向到客户端回调地址。
3. 主进程仅接受预期回调路径、端口和 `state`；通过 HTTPS 向认证服务提交授权码、PKCE verifier 和精确回调地址换取会话。授权码、会话令牌和第三方平台令牌均不得写入可见日志或传给 Renderer；回调 URL 中不得包含会话令牌。
4. 主进程再次向服务端确认会话有效、取得服务端用户 ID 后，才切换到该账号的数据目录并开放业务 IPC。回调超时、取消、错误或网络中断时保持锁定，允许用户重新点击 Sign in；旧请求立即作废。关闭浏览器但没有回调时按超时处理。
5. Web 页提供登录结果及“返回客户端”状态；若自动回跳失败，提示重试或手动返回客户端，不显示任何可复制的会话凭据。退出或切换账号时立即停止旧任务、清除本机受保护凭据并锁定客户端，同时请求服务端撤销会话；离线撤销失败须明确提示，会话在服务端过期前仍可能有效。

## 安全边界

1. 服务端是账号与会话的唯一可信来源。短信验证码只在服务端生成、限时、限次数、单次使用，并限制 IP 与手机号发送频率。第三方回调由服务端核对一次性 `state`；Web 登录会话 Cookie 使用 Secure、HttpOnly、SameSite 属性及相应 CSRF 防护；客户端不接收平台密钥。
2. 认证服务的业务接口默认要求有效会话。匿名白名单仅包括健康检查、Web 登录所需的启动、短信发送及验证、第三方回调和桌面端一次性授权码交换。每个接口限制请求方法、正文大小、请求速率；错误不透露账号是否存在。授权码必须短期、单次使用，绑定发起请求、精确回调地址和 PKCE 挑战。
3. Electron 主进程对所有现有业务 IPC 统一检查可信 Renderer 来源和当前已验证会话。登录相关 IPC 单独列白名单。React 锁定页只是交互层，不能充当权限边界；本地回调监听仅绑定回环地址，验证来源状态并在完成、取消或超时后关闭。
4. 会话凭据只保存在操作系统保护的存储中；渲染进程不读取 token。服务端只保存 token 摘要，支持过期、轮换和主动撤销。退出或切换账号时停止任务、关闭窗口并重新初始化账号数据。
5. 本地按服务端用户 ID 划分数据目录。目录名必须通过严格 UUID 校验，不接受 Renderer 传入的路径。旧全局数据原样留存，不自动关联任何账号。
6. 客户端锁定页的视觉背景不得承载认证信息或妨碍操作。若后续采用动效，须支持减少动态效果、渲染不可用时回退并限制资源消耗；Sign in、登录状态和重试始终可操作。Web 表单在窄屏下也必须可用。

## 当前实现与设计差距（2026-09-20）

- 已接入 Web 短信登录页、一次性授权码与 PKCE 交换、系统浏览器回跳、客户端锁定页和业务 IPC 门禁；服务端短信验证不再直接返回客户端会话令牌。
- 每个已验证账号使用独立本地数据目录。旧 MySQL 会话表不含账号字段，因此认证后的客户端暂时固定使用账号目录内的 JSON 持久化存储，不连接该共享 MySQL 库；后续若恢复 MySQL，必须先完成账号字段与查询约束。
- QQ/微信官方授权服务端适配已编码，但真实平台资质与联调、账号跨方式绑定、HTTPS 部署、真实 MySQL 联调、跨账号与恶意场景人工验收仍待完成，当前不能视为正式交付。

## 验收

- 全新安装只显示客户端锁定页；无会话调用对话、插件、工作区、设置等业务 IPC 被拒绝。点击 Sign in 在系统浏览器打开 HTTPS Web 登录页，客户端不出现认证表单。
- 真实短信和 QQ/微信在 Web 端可创建/复用账号；错码、过期码、重放、错误 `state`、错误 PKCE verifier、伪造或重复回调均失败，客户端始终保持锁定。
- 浏览器完成登录后仅一次性授权码回到客户端；主进程完成交换及在线会话确认后才解锁。取消、超时、关闭浏览器后等待超时和回跳失败均可安全重试，不泄露凭据。
- 切换账号不串读本地数据；退出后无法继续运行旧任务或调用业务接口。
- 会话过期、服务端撤销、网络中断均保持锁定；恢复网络后须重新验证。
- 客户端锁定页与 Web 登录页在常规和窄窗口可用；若采用动效，动效关闭或失效时仍可启动和完成认证。
