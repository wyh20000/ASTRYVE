# 04 · 第二阶段计划（P2：模型基础能力 + 回复样式优化）

> 二阶段目标：让模型具备**识图分析**等基础能力（**不含 coding 与浏览器操控**），并优化 AI 回复样式。
> 承接 P1（页面样式 + 会话系统），在已实现的「模型流式对话 / 多预设 / 推理等级」之上，扩展**多模态与文件 / 文档 / 搜索能力**。
> 技术基线：React + TS + Electron（electron-vite）+ Tailwind + Zustand + mysql2（文件兜底），模型走 OpenAI 兼容 API。

---

## 1. 阶段目标

1. **识图分析**：用户可「剪贴板粘贴 / 拖拽 / 文件选择」上传图片，走视觉模型流式分析（描述、OCR、问答）。
2. **常见能力**：文档解析（PDF / Word / Excel）、表格数据分析（CSV）、通用文本能力（总结 / 翻译 / 改写 / 解释 / 头脑风暴）。
3. **联网搜索（可选）**：Kimi `$web_search` 与 DeepSeek Responses API `web_search`，均由模型平台执行检索，无需第三方搜索 key。
4. **回复样式优化**：markdown 完整渲染、代码块统一（语言标签 + 复制）、结构块与流式态精修、对照设计稿走查。

> 本阶段**不引入 agent 工具调用（function calling）框架**，能力靠「多模态输入 + 提示词 + 多轮上下文」实现。

---

## 2. 范围

### 2.1 范围内（Do）
- **多模态输入**：图片粘贴 / 拖拽 / 文件选择；图片附件气泡渲染（缩略图、移除、上传态）。
- **识图分析**：视觉模型（OpenAI 兼容 `image_url` + base64）流式回复；按模型预设区分「是否支持视觉」。
- **文档解析**：PDF / Word(.docx) / Excel(.xlsx) 在**主进程**提取文本 → 注入上下文 → 模型总结 / 问答。
- **表格数据分析**：CSV 读取 → 注入上下文 → 模型做统计、解释、问答。
- **通用文本能力**：系统提示定位为通用助手（总结 / 翻译 / 改写 / 解释 / 头脑风暴等，模型原生能力）。
- **联网搜索（可选）**：Kimi `$web_search` 与 DeepSeek Responses API `web_search` → 回复附带「引用来源」块；自定义提供方隐藏。
- **回复样式**：markdown（表格 / 列表 / 引用 / 行内代码 / 链接 / 标题 / 分隔线）、代码块统一、结构块折叠与视觉、流式动画、空态。

### 2.2 范围外（Not do，一律不做）
- **coding**：文件树 / 代码编辑器 / 终端执行 / 真实文件写入（回归 P3）。
- **浏览器操控**：Playwright / DevTools 自动化（回归 P4）。
- **agent 工具调用框架**：function calling / 工具编排（后续阶段再评估）。
- 插件、账号、云同步、多端、国际化。

## 3. 边界决策（已与需求方确认）

| 事项 | 决策 |
| --- | --- |
| 联网搜索 | 使用提供方的**平台内置搜索**：Kimi 走 `$web_search` 两轮闭环，DeepSeek 走 Responses API `web_search` 服务端自动续推；零第三方搜索 key、零浏览器 |
| 视觉模型 | **按当前模型自身能力区分**：不配置备用视觉模型，也不在发图时自动切换模型；DeepSeek 等纯文本模型发图时直接拦截发送 |
| 视觉模型配置 | 多模态模型作为独立预设配置（如 `moonshot-v1-8k-vision-preview` / `kimi-k3`），由用户在对话输入区显式切换 |
| 能力范围 | 「越全越好」，但纯多模态 + 提示词，不引入工具调用框架 |

## 5. 数据模型与 IPC 变更

### 5.1 `src/shared/types.ts`

```ts
// 附件（P1 已预留，P2 正式启用）
export interface Attachment {
  id: string
  kind: 'image' | 'file' | 'url'
  name: string
  contentType: string
  dataRef: string // 图片：base64 dataURL；文档：原文 base64（仅主进程解析用）
  meta?: {
    sizeBytes?: number
    width?: number
    height?: number
    extractedText?: string // 文档解析后的纯文本，注入上下文
  }
}

// Message 增加附件
export interface Message {
  // ...现有字段
  attachments?: Attachment[]
}

// 发送入参增加附件
export interface SendMessageInput {
  sessionId: string
  content: string
  attachments?: Attachment[]
}

// 模型预设只保存实际调用的模型；图片能力由当前 model 标识判断
export interface ModelPreset {
  // ...现有字段
  model: string
}
```

### 5.2 `src/shared/ipc.ts` 与 preload

- `message:send` 入参扩展 `attachments`（现有 channel 不变，仅加字段）。
- `model:*` 不变（`setConfig` 已通用，preset 结构扩展后自然携带视觉字段）。
- 联网搜索不新增 IPC：复用 `message:send`；主进程按提供方选择 Kimi Chat Completions `$web_search` 或 DeepSeek Responses API `web_search`（见 §7）。

### 5.3 存储
- 图片 base64 随消息持久化（MySQL `attachments` 列 MEDIUMTEXT / 文件兜底 JSON）；发送前**渲染端压缩**（≤ 约 1568px，JPEG/PNG），控制体积。
- 文档解析后的 `extractedText` 仅注入上下文，**不落库**（原始文件 base64 可选择性丢弃，避免膨胀）。

## 6. 视觉 / 多模态技术要点

- **请求形态**：OpenAI 兼容 `content` 支持数组：
  ```ts
  type ChatContent = string | Array<
    | { type: 'text'; text: string }
    | { type: 'image_url'; image_url: { url: string } } // base64 dataURL
  >
  ```
- **模型能力判断**：发送含图消息时，根据当前预设的 `model` 标识判断其自身是否为多模态模型；纯文本模型不发送请求，也不保存本次消息。
- **无自动路由**：请求始终使用当前预设的 `model`。如需识图，用户需单独配置 `moonshot-v1-8k-vision-preview` / `kimi-k3`（Kimi，[官方文档](https://platform.kimi.com/docs/guide/use-kimi-vision-model)）或其它 OpenAI 兼容多模态模型（Qwen-VL / GLM-4V / GPT-4o），并在对话中显式切换。
- **不支持提示**：用户用纯文本模型发送图片时，仅显示一次 message 提示「信息不能发送，此模型无法进行图片处理」；不在对话区域插入用户消息或错误回复。
- **流式**：复用现有 `streamChat`，仅扩展 `messages` 的 `content` 结构，流式回调逻辑不变。

## 7. 联网搜索设计（提供方内置搜索，可选）

- **Kimi 机制**：声明 `$web_search`（`builtin_function`），收到 `tool_calls` 后原样回传参数，再流式取得最终答案。
- **DeepSeek 机制**：请求官方 `/responses`，声明 `{ type: 'web_search' }` 并指定 `tool_choice`；搜索、最多多轮续推及最终输出由服务端完成。参见 [DeepSeek Responses API](https://api-docs.deepseek.com/zh-cn/guides/responses_api/)。
- **边界**：仅适配两种提供方的内置搜索协议，不建设通用工具框架。
- **触发**：输入框「联网搜索」开关默认关闭；当前提供方为 Kimi 或 DeepSeek 时显示，自定义端点隐藏。
- **降级**：任一搜索协议失败时清空搜索分支的部分内容，回退普通回答并显示独立提示。
- **来源展示**：若模型返回检索来源，渲染「引用来源」块（可点击、新窗口打开）。

## 10. 验收标准（Definition of Done）

1. 图片可粘贴 / 拖拽 / 选择上传，当前多模态模型正确流式作答；纯文本模型发图时不发送、不落库、不在对话区报错，仅显示明确的 message 提示。
2. PDF / Word / Excel / CSV 可上传并问答；解析失败有提示；大文件不阻塞 UI。
3. 总结 / 翻译 / 改写 / 解释等文本能力正常；多轮上下文衔接正确。
4. Kimi / DeepSeek 联网搜索返回结果并展示引用来源；自定义提供方隐藏入口；请求失败回退普通回答。
5. markdown 表格 / 列表 / 引用 / 行内代码 / 链接 / 标题渲染齐全；用户与 AI 的代码块均有「语言标签 + 复制」且高亮生效。
6. 结构块可折叠、思考块动画、流式态美观；整体对比度 / 间距 / 三态达标。
7. `npm run typecheck` 与 `npm run build` 通过；不引入任何真实 FS 写 / 终端 / 浏览器自动化。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 视觉模型端点/名称变动 | 图片能力误判或识图失败 | 多模态模型作为独立预设配置；集中维护模型标识识别规则，并允许用户在对话中显式切换 |
| 大图片 / 大文档 | 体积与卡顿 | 渲染端压缩图片；文档只注入提取文本、原始 base64 不落库 |
| 文档解析依赖 | 编译/体积 | 选纯 JS 库（pdf-parse/mammoth/xlsx），无原生编译 |
| 提供方搜索协议不同 | 共用协议会请求失败 | Kimi 与 DeepSeek 分别适配；失败统一回退普通回答 |
| 范围蔓延（想顺手做编码/工具） | 进度失控 | 严守 §2.2 范围外清单 |
