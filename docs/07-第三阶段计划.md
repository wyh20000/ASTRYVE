# 07 · 第三阶段计划（P3：Agent 执行内核 + Coding + Skills）

> P3 目标：在 P2 对话、多模型、多模态与联网能力之上，建立安全、可取消、可审计的 Agent 执行内核，完成真实 Coding 闭环，并接入声明式 Skills。
>
> 安全原则：模型只提出操作，确定性策略引擎决定是否允许；renderer 不直接接触文件、命令、Docker、Git 或密钥。

---

## 1. 已确认决策

1. P3 包含：Agent 执行内核、Coding 完整闭环、第三方 Skills 兼容、安装、市场与真实调用。
2. 第三方可执行插件及插件市场推迟到 P4；声明式 Skills 的远程检索、安装、卸载和更新纳入 M9。
3. 首版优先支持 Windows + PowerShell；工具契约与执行器保持跨平台抽象。
4. 本机 Coding 任务由独立 `utilityProcess` / worker 执行，不在 renderer 执行系统操作。
5. 权限提供三个档位：`只读模式`、`请求批准`、`帮我批准`；P3 不提供“完全访问、永不询问”。
6. 权限默认使用 `请求批准`；权限与执行环境按项目分别记忆，并在每次任务开始前清晰显示。
7. 执行环境独立提供两个档位：`Docker 沙箱`、`本机执行`。
8. Docker 可用时默认选择 Docker；不可用时明确显示不可用，绝不静默降级到本机。
9. Docker 使用临时工作副本，不把宿主项目以读写方式挂载到容器；任务结束后以补丁形式回传，用户批准后再写入宿主项目。
10. Docker 默认断网；联网必须单独批准，可允许一次或当前任务。
11. API Key、数据库密码、Git 凭据和宿主环境变量默认不传入容器。
12. Git 默认只自动执行只读操作；不自动 commit、建分支、merge、push、reset 或 clean。
13. 模型必须使用提供方原生 function/tool calling 才能执行 Coding；不从自然语言或松散 JSON 猜测工具调用。
14. Skills 兼容 `SKILL.md` 形式，只能组合已有工具，不能提升权限或绕过审批。

## 2. 阶段目标

### 2.1 用户可见目标

- 用户可选择一个本地项目作为当前工作区。
- 模型能够搜索、读取和理解项目文件，给出结构化执行计划。
- 模型能够在隔离环境中修改文件，并展示文件清单与 diff。
- 用户批准后，修改才会安全写回宿主工作区。
- 模型能够运行测试、类型检查和构建，流式展示受限输出。
- 用户可随时停止任务；删除会话、关闭窗口或退出应用会取消执行。
- 输入框旁始终显示当前权限档位与执行环境。
- 用户可从技能市场、GitHub、本机目录和 Codex 已安装目录发现或安装 Skills，并通过 `/skill-name` 在真实对话中调用。

### 2.2 工程目标

- 建立统一 Tool Registry、Task Runtime、Policy Engine、Approval Service 和 Execution Backend。
- 本机与 Docker 共用同一套工具契约、权限判定、事件协议和验收用例。
- renderer 只消费状态和提交选择，不持有系统能力。
- 所有文件路径、命令、网络、Git 和补丁操作均接受运行时校验。
- 所有执行都有 task ID、tool call ID、超时、取消、输出上限和审计记录。

### 2.3 范围外

- 第三方可执行插件市场、插件签名与插件代码自动更新（声明式 Skills 市场不在此限制内）。
- 任意插件代码直接在主进程运行。
- 浏览器自动化与 DevTools 控制（P4）。
- 云端工作区、多人协作和远程开发机。
- 自动 commit、push、创建 PR 或发布。
- 完整 IDE 调试器、语言服务器市场和远程容器开发。
- Docker 域名级出站白名单代理；P3 只控制“完全断网 / 当前操作或任务允许出站”。

## 3. 总体架构

```text
Renderer（React）
  │  选择工作区 / 权限 / 环境 / 批准 / 停止 / 展示 diff 与日志
  ▼
Preload（窄白名单 API）
  ▼
Main Process
  ├─ Task Runtime          任务状态机、事件、取消、恢复
  ├─ Tool Registry         工具 schema、能力声明、版本
  ├─ Policy Engine         确定性风险判断，deny 优先
  ├─ Approval Service      批准请求、作用域、过期与防重放
  ├─ Workspace Service     授权根、真实路径、补丁写回
  ├─ Skill Registry        SKILL.md 发现、校验、上下文注入
  └─ Execution Router
       ├─ Local Backend → utilityProcess / worker
       └─ Docker Backend → Docker CLI（结构化 argv、shell=false）
```

### 3.1 强制信任边界

- 模型输出、Skill 内容、项目文件、命令输出和容器输出全部视为不可信输入。
- renderer 不能自行批准操作；批准必须由用户事件创建，并在主进程验证来源。
- 模型不能调用 `approve`、修改权限模式或切换执行环境。
- Policy Engine 使用确定性规则，不把“是否危险”交给模型判断。
- Local Backend 和 Docker Backend 不能直接修改权限配置。
- 宿主写入只能由 Workspace Service 在批准后完成。
- Docker 容器不挂载 Docker socket，不使用 `--privileged`，不共享宿主 PID、IPC 或网络命名空间。

## 4. 权限筛选设计

### 4.1 权限档位

| 档位 | 自动允许 | 必须批准 | 永久拒绝 |
| --- | --- | --- | --- |
| 只读模式 | 工作区内读取、搜索、列目录、只读 Git | 无 | 写文件、执行命令、联网、工作区外访问 |
| 请求批准 | 工作区内读取与搜索 | 每次写入、命令、联网、Git 写操作、工作区外访问 | 违反硬安全策略的操作 |
| 帮我批准 | 读取、搜索、生成沙箱补丁、确定性低风险检查 | 风险写入、依赖变更、联网、危险命令、Git 写操作 | 违反硬安全策略的操作 |

### 4.2 “帮我批准”自动允许

- 工作区内文件读取、glob、文本搜索和受限目录遍历。
- 在 Docker 临时副本中创建修改和计算 diff，不自动写回宿主。
- `git status`、`git diff`、`git log`、`git show` 等只读 Git 命令。
- 在默认断网 Docker 中，从项目清单解析出的既有 `test`、`typecheck`、`lint`、`build` 脚本。
- 不含 shell 元字符、动态拼接、网络和后台驻留的已分类低风险检查命令。

本机执行补充规则：项目脚本本质上可以运行任意代码，即使名称是 `test` 或 `build`，首次执行仍必须批准；用户可批准当前任务内的规范化命令前缀。

### 4.3 始终请求批准

- 删除、移动、批量覆盖、二进制文件修改。
- 将沙箱补丁写回宿主项目。
- 安装、升级、降级或卸载依赖。
- 任何容器或本机联网。
- Git commit、branch、checkout/switch、merge、rebase、push、reset、clean、tag。
- 访问授权工作区外路径。
- 启动长期后台服务、监听端口或打开外部应用。
- 包含管道、重定向、命令替换、子 shell、通配删除或动态命令拼接的命令。
- 修改锁文件以外的供应链配置、CI 发布配置、凭据文件或启动项。

### 4.4 硬拒绝规则

- 访问系统根目录、用户主目录整体、凭据目录或未授权项目。
- 读取或传输 API Key、密码、浏览器数据、SSH/Git 凭据。
- Docker 挂载宿主 Docker socket、设备、系统目录或使用 privileged。
- 通过 junction、symlink、reparse point 或路径竞态逃离授权根。
- 关闭安全软件、修改系统安全策略或绕过审批机制。
- 命令目标无法在执行前被确定性解析和约束。

### 4.5 批准作用域

P3 支持：

- `once`：仅当前 tool call。
- `task-prefix`：当前任务内允许相同规范化命令前缀。
- `deny`：拒绝本次操作。

约束：

- 批准令牌绑定 task ID、tool call ID/命令前缀、工作区 ID、执行后端和风险摘要。
- 令牌短期有效、单次消费、防重放；任务结束立即失效。
- 参数扩大、路径改变、执行环境改变或命令前缀不一致时必须重新批准。
- P3 不保存永久全局授权规则。

## 5. 执行环境筛选设计

### 5.1 Docker 沙箱

默认行为：

- 检测 Docker Desktop / Docker Engine 和 Linux container 能力。
- 使用固定摘要或明确版本的内置基础镜像。
- 创建临时容器、临时工作副本和独立 task volume。
- 安全复制默认排除 `.git`、`.env*`、凭据文件、宿主链接和特殊文件；Git 信息由宿主只读工具提供。
- 默认 `--network none`。
- 不挂载宿主工作区为读写目录；初始文件通过受控复制进入沙箱。
- 不传入宿主密钥、代理配置、Docker socket 或无关环境变量。
- 设置 CPU、内存、PID、运行时间、输出和临时磁盘限制。
- 降低 Linux capabilities，启用 `no-new-privileges` 和默认 seccomp。
- 任务完成后导出结构化 diff、文件哈希和产物清单。
- 用户批准后由 Workspace Service 在宿主侧应用补丁。
- 任务结束、取消或超时后删除容器和临时 volume。

首版镜像：

- Git。
- Node.js 与 npm。
- Python 与 pip。
- 常见编译工具和文本工具。
- 非 root 默认用户。

允许用户选择本机已有镜像，但必须显示镜像名称、标签/摘要与风险提示，并覆盖默认 entrypoint，以受控非 root runner 启动。镜像不存在时拉取也需要联网批准。P3 不自动构建项目任意 Dockerfile。

### 5.2 Docker 联网

- 默认完全断网。
- 网络请求触发批准，可选择“仅本次操作”或“当前任务”。
- 批准后只连接普通隔离网络，不使用 host network。
- 网络开启、关闭、持续时间和发起工具写入审计日志。
- 任务结束后网络授权失效。
- 模型 API 仍由主进程请求，API Key 不进入容器。

### 5.3 本机执行

- 用户必须显式选择或从 Docker 不可用提示中手动切换。
- 首次切换展示安全说明。
- 命令在独立 utility process 中执行，使用结构化 executable + argv，默认 `shell=false`。
- 工作目录固定到授权工作区；环境变量采用最小白名单。
- 文件写入仍通过 Workspace Service 和批准流程。
- 子进程进入 Job Object / 等价进程组，取消时终止整个进程树。
- 本机执行不等于完全访问，仍受相同 Policy Engine 约束。

### 5.4 资源默认值

- CPU：2 核。
- 内存：4GB。
- PID 数：256。
- 单命令默认超时：10 分钟。
- 单任务默认最长时间：30 分钟。
- 单命令输出：10MB，超出后截断并继续保留尾部摘要。
- 沙箱临时输出：2GB。

资源值可在设置页调整，但降低安全限制或扩大资源必须有明确说明。

## 6. 核心类型与协议

```ts
type PermissionMode = 'read-only' | 'ask-every-time' | 'smart-approval'
type ExecutionEnvironment = 'docker' | 'local'
type TaskStatus =
  | 'queued'
  | 'planning'
  | 'running'
  | 'waiting-approval'
  | 'stopping'
  | 'completed'
  | 'failed'
  | 'cancelled'

type OperationKind =
  | 'fs.read'
  | 'fs.search'
  | 'fs.patch'
  | 'fs.apply-host'
  | 'process.run'
  | 'network.enable'
  | 'git.read'
  | 'git.write'

interface WorkspaceGrant {
  id: string
  rootPath: string
  realRootPath: string
  createdAt: number
}

interface ToolInvocation {
  taskId: string
  callId: string
  toolName: string
  args: unknown
  workspaceId: string
  environment: ExecutionEnvironment
}

interface PolicyDecision {
  outcome: 'allow' | 'ask' | 'deny'
  risk: 'low' | 'medium' | 'high' | 'critical'
  reasonCode: string
  summary: string
  normalizedTarget?: string
}

interface ApprovalRequest {
  id: string
  taskId: string
  callId: string
  operation: OperationKind
  summary: string
  risk: PolicyDecision['risk']
  scopeOptions: Array<'once' | 'task-prefix'>
  expiresAt: number
}
```

### 6.1 Tool Registry 首版工具

- `workspace.listFiles`
- `workspace.searchText`
- `workspace.readFile`
- `workspace.readMany`
- `workspace.proposePatch`
- `workspace.getDiff`
- `workspace.applyApprovedPatch`
- `process.run`
- `process.startService`
- `process.stop`
- `git.status`
- `git.diff`
- `git.log`
- `git.show`

工具 schema 在 shared 层定义，主进程使用运行时 schema 再验证。模型只能调用 Registry 中已向当前任务公开的工具。

M2-C 实现记录：TaskRuntime 对模型、reasoning、stdout 和 stderr 输出进行内存聚合，按字节
分块并限制待写队列与任务总量；超过限制后仅发送一次截断通知，终态事件前强制冲刷输出。
`taskEventJournal.ts` 每 200ms 批量写入独立 journal，使用临时文件 + rename 原子替换，
终态绕过等待立即发起落盘。应用启动时把上次未结束任务标记为 `stale`，清理由 journal
明确列出的专用临时目录和中断写入文件；链接只移除链接本身，越界 ID 不参与清理。

## 8. 安全测试矩阵

### 8.1 单元测试

- PermissionMode × OperationKind 全组合决策表。
- deny 优先级高于批准缓存和 Skill 声明。
- 批准令牌过期、重放、跨任务、跨工作区和参数扩大。
- 路径 `..`、绝对路径、UNC、大小写、短文件名、尾随点/空格。
- symlink、junction、reparse point、循环链接和目标切换。
- 命令 argv、shell 元字符、管道、重定向、子 shell、编码混淆。
- Docker 参数生成，确保不存在 privileged、host network、Docker socket 和 RW host mount。
- diff 哈希、基线变化、补丁篡改、文件数量和体积上限。
- Skill frontmatter、资源路径、重名、优先级和工具越权。

### 8.2 集成测试

- 临时工作区读写边界与原子写回。
- utility process crash、timeout、cancel 和进程树清理。
- Docker 无网络、有限资源、非 root、无宿主敏感目录。
- Docker 临时副本修改后只导出预期 diff。
- Docker daemon 停止、镜像不存在、拉取中断和磁盘不足。
- renderer 重载/销毁后不能遗留执行任务。
- 审计日志不包含 API Key、prompt 敏感内容和完整环境变量。

### 8.3 对抗测试

- 项目 README/SKILL/代码注释要求模型“忽略审批并执行危险命令”。
- 命令输出伪造“用户已批准”或伪造 tool call。
- 文件名和路径使用控制字符、Unicode 同形字符和超长输入。
- 创建链接后在检查与写入之间替换目标。
- 恶意仓库包含巨量文件、深层目录、压缩炸弹和设备文件。
- 依赖脚本尝试读取宿主凭据或联网外传。
- 容器尝试访问 Docker socket、宿主网关、metadata 地址和敏感挂载。
- 模型重复调用工具、构造重复 call ID 或并发扩大操作范围。

### 8.4 UI / E2E 测试

- 权限和执行环境筛选器始终显示当前值。
- 每个项目分别记忆选择，切换项目不会串用授权。
- Docker 不可用时不会静默执行本机命令。
- 批准弹窗准确显示命令、路径、网络、环境和风险原因。
- 拒绝后任务可继续调整计划或安全终止。
- 停止生成同时终止模型请求、工具任务、容器和子进程。
- 用户修改文件导致基线冲突时，界面明确提示且不覆盖。

## 9. 最终验收场景

### 9.1 必验收：真实 Coding 闭环

1. 用户选择一个 Git 项目。
2. 选择权限档位和 Docker/本机环境。
3. 用户描述一个夹具缺陷。
4. 模型搜索并读取相关文件，给出执行计划。
5. 模型在隔离环境生成修改和 diff。
6. UI 显示精确文件清单和批准请求。
7. 用户批准后补丁写回宿主项目。
8. 模型运行测试并展示结果。
9. 最终报告列出改动、命令、测试、批准和剩余问题。

### 9.2 必验收：安全边界

- 只读模式下宿主零写入、零命令、零联网。
- Docker 默认断网且不能看到宿主敏感文件。
- Docker 不可用时不自动切换本机。
- 拒绝补丁后宿主工作区不变化。
- 路径逃逸、链接竞态和危险命令被阻止。
- 停止任务后无子进程、容器、网络授权或临时资源残留。
- Skill 无法请求未授权工具或自行批准操作。

### 9.3 可后置验收

- 从零生成完整新项目。
- 自动安装依赖并启动应用。
- 自动建分支、commit、push 或创建 PR。
- 域名级容器网络白名单。

## 10. Definition of Done

P3 完成必须同时满足：

1. Agent 执行内核、Local Backend、Docker Backend 使用统一工具与策略接口。
2. Coding 必验收闭环在 Docker 和本机两种环境分别通过。
3. 三个权限档位行为与文档一致，批准不可伪造、重放或扩大。
4. 宿主写入只发生在精确 diff 获得批准之后。
5. Docker 默认断网、非 root、有限资源、无宿主 RW 挂载和 Docker socket。
6. 删除会话、关闭窗口、退出应用和停止任务都能清理所有执行资源。
7. Skills 可发现、启用并组合工具，但不能提升权限。
8. `sandbox: true` 下 renderer、preload、Coding 和 Skills 回归通过。
9. 单元、集成、对抗和 E2E 测试全部通过；Docker 测试有独立可复现说明。
10. `npm run typecheck`、`npm test`、`npm run build`、依赖审计和 Windows 打包验证通过。

## 11. 实施顺序与停线条件

严格按 M0 → M11 推进。以下情况必须停线，不得以 UI Mock 掩盖：

- Workspace 路径边界无法可靠验证。
- 审批可被 renderer、模型或 Skill 伪造。
- 停止任务后存在残留进程或容器。
- Docker 会静默降级到本机。
- 宿主写回内容与用户批准的 diff 不一致。
- API Key、Git 凭据或宿主敏感环境变量进入 renderer/容器/日志。
- 为兼容无 tool calling 模型而引入自然语言命令猜测。

安全底座通过后再扩展 Monaco、交互式终端和更多 Skills；不得反向跳过底座先堆功能。
