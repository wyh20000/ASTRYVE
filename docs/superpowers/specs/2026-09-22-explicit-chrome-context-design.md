# ASTRYVE 统一能力选择与显式 Chrome 上下文设计

> 日期：2026-09-22
> 状态：待实现
> 适用仓库：`AIAGENT-New`
> 依赖：现有 Browser Gateway、Google Chrome DevTools MCP 1.7.0、任务工具审批与审计链路

## 1. 背景

当前浏览器任务由宿主根据用户正文中的 URL、"浏览器"、"页面"、"截图"、"点击"等词判断
`browserIntent`。命中后，宿主向模型注册 `browser.*` 工具，并通过提示词要求模型使用 Chrome。
这种方式存在四个问题：

1. 用户看不到本轮是否启用了 Chrome，也不能在发送前明确关闭。
2. 普通讨论网页、浏览器或 Bug 时可能误触发；简短追问又可能漏触发。
3. "当前页面"没有明确绑定对象，用户切换标签页后目标可能变化。
4. 浏览器读取结果容易只停留在工具轮次，后续消息可能只继承助手过渡语而丢失页面证据。

同时，现有输入区使用 `/skill` 选择 Skill、使用 `@plugin` 选择插件，插件 MCP、插件 Hook 和自动匹配
能力的调用时机没有形成一套用户可预测的规则。用户难以区分“已安装”、“本轮已选择”、“模型已选中
具体工具”和“工具已经执行”。

本设计不引入 Chrome 扩展，不改变官方 Chrome DevTools MCP 传输。目标是对齐 Codex 的能力分层：
Skill 可以按语义匹配或由 `$skill-name` 显式选择；插件是能力包，不被直接“执行”；MCP 工具只在模型
选择具体工具后调用；Hook 只由生命周期事件触发。Chrome 因为涉及实时浏览器上下文，额外要求用户先
显式绑定标签页和模式，模型才能看到受限的浏览器工具。

## 2. 设计目标

- 输入区不新增独立浏览器按钮；将现有附件/图片入口收敛为一个 `+` 上下文菜单，Chrome 作为其中一项。
- Skills、插件和 Chrome 共用同一个 `+` 菜单，同时保留 Codex 风格的 `$skill-name` 与 `@plugin-id`
  键盘入口，不增加常驻控件。
- 明确区分安装/启用、自动匹配/显式选择、任务快照、工具选择、审批、执行和审计七个阶段。
- 自动匹配的 Skill 或插件能力在任务时间线中可见；用户显式选择的能力在发送前显示为可移除标签。
- 未绑定 Chrome 时不向模型注册任何 `browser.*` 工具。
- 自然语言识别只能提醒用户选择 Chrome，不得直接连接 MCP 或执行浏览器工具。
- 用户可以在一个弹出层内选择当前标签页或指定标签页，并选择只读或交互模式。
- 浏览器绑定进入可信请求结构，不能由模型、网页或插件返回内容修改。
- 保留现有网站 allowlist/blocklist、高风险审批、审计、截止时间和取消机制。
- 每轮回复结束仍可关闭官方 MCP 子进程；跨轮不复用失效的 page ID 或元素 UID。
- 浏览器读取结果以有界、结构化证据进入后续上下文，不依赖助手自述。

## 3. 非目标

- 不实现 Chrome 工具栏入口、浏览器侧边聊天、选中文本转发或扩展 Native Messaging。
- 不让 Skills、普通插件、MCP 返回或网页内容自行开启浏览器能力。
- 不把 Chrome DevTools MCP 原始工具直接暴露给模型或普通插件。
- 不把插件呈现为单个可执行工具，也不为 MCP 或 Hook 增加独立常驻按钮。
- 不在本批次重做插件安装市场、MCP 连接设置或 Hook 配置管理页面。
- 不承诺文本模型能够理解截图像素；视觉回传能力按模型能力单独处理。
- 不读取 Cookie、完整浏览历史、密码、验证码、支付信息或其他现有 Gateway 禁止的数据。

## 4. 统一 `+` 上下文菜单

### 4.1 输入区形态

输入区工具栏使用一个固定尺寸的 `ContextMenuButton`（`+` 图标），替换当前并排的附件和图片按钮。
本设计不再增加独立 `BrowserControl`。点击 `+` 后打开与参考交互一致的菜单，一级菜单包含：

- `上传文件`：统一打开图片和受支持文档选择器；粘贴和拖拽行为保持不变。
- `使用 Chrome`：打开右侧子面板或二级菜单。
- `Skills`：搜索并显式选择已启用 Skill；等价于在正文使用 `$skill-name`。
- `插件`：搜索并显式选择已安装且启用的插件；等价于在正文使用 `@plugin-id`。

本批次不新增"添加到项目"或"最近的文件"能力；菜单结构为后续上下文来源保留扩展位置，只收敛
现有上传、Skill/插件选择能力并增加 Chrome。

```text
+
├─ 上传文件
├─ 使用 Chrome                         >
   ┌────────────────────────────────────┐
   │ 模式              [只读 | 交互]   │
   │ 当前活动标签页                    │
   │ 禅道 Bug #33582       192.168...  │
   │ GitHub Pull Request   github.com   │
   │ ───────────────────────────────── │
   │ 刷新标签页              关闭绑定  │
   └────────────────────────────────────┘
├─ Skills                              >
│  ├─ 搜索已启用 Skill
│  └─ 选择后显示 `$skill-name` 标签
└─ 插件                                >
   ├─ 搜索已安装且启用的插件
   └─ 选择后显示 `@plugin-id` 标签
```

`+` 放在输入工具栏左侧、模型选择器之前；发送/停止按钮继续固定在右侧。菜单向可用空间展开，空间
不足时 Chrome 子面板改为覆盖一级菜单，而不是把输入框撑宽。

Chrome 子面板内容：

1. 状态操作：关闭 Chrome 上下文或刷新标签页。
2. 模式分段控件：`只读` / `交互`。
3. 标签页列表：`当前活动标签页`以及官方 MCP 返回的有界标题和来源。
4. 当前选择摘要和连接错误；敏感 URL 只显示清洗后的来源与限长标题。

选择完成后菜单关闭，并在 Sender `header` 中显示可移除的上下文标签，例如
`Chrome · 禅道 · 只读`、`$review` 或 `@github`。标签用于确认和移除显式选择，不是第二个常驻
工具栏入口。没有显式选择时不显示标签；窄窗口限制标签最大宽度并截断标题。

输入语法与菜单必须写入同一份结构化草稿状态，不能各自维护一套结果：

- `$skill-name`：Codex 风格的显式 Skill 选择；插件提供的 Skill 也使用 `$`。
- `@plugin-id`：显式选择插件能力包。
- `+` 菜单：为不记得名称的用户提供鼠标和键盘可发现入口，选择结果与上述语法等价。
- 旧 `/skill-name`：只作为有期限的兼容别名，解析后提示迁移到 `$skill-name`，不得长期作为主语法。
- 自动匹配的 Skill 或插件不伪装成用户手动标签，而是在发送后的任务时间线中记录来源和原因。

`+` 按钮保持稳定尺寸：加载、选中、错误和动态标签页内容不得改变工具栏布局。存在 Chrome 绑定时
可在 `+` 图标上显示小状态点；错误或 stale 使用同一状态点和上下文标签呈现，不插入新按钮。

Skills 和插件子面板只读取本地注册表元数据，不启动 MCP、不执行插件 Worker 或 Hook。需要连接、
认证或审批的状态可在条目中展示，但连接动作仍进入现有设置/授权流程，选择条目本身不等于授权。

### 4.2 连接时机

- 打开 `+` 一级菜单不启动 MCP；进入 Chrome 子面板但尚未请求真实列表时也不读取页面正文。
- Chrome 子面板首次加载真实标签页或用户选择"刷新"时，宿主建立短租约并只调用 `list_pages`。
- 选择 Chrome 不读取页面正文；真正的 `inspect`、截图或交互发生在消息发送后的工具轮次。
- Chrome 未开启远程调试或用户拒绝官方连接时，错误显示在弹出层。绑定仍开启时不得静默降级为
  普通聊天；用户可以从同一个 `+` 菜单或上下文标签中关闭绑定后再发送普通消息。

### 4.3 提醒而非自动执行

保留轻量浏览器意图检测仅用于 UI 提醒。例如用户输入"查看当前页面"时，可给
`+` 按钮增加一次非阻塞提示状态，或在菜单中的 Chrome 项旁显示提示点。该检测不得：

- 创建浏览器任务；
- 启动 Chrome DevTools MCP；
- 自动选择标签页或模式；
- 修改已保存的浏览器绑定。

### 4.4 统一能力生命周期

所有能力统一使用以下阶段，产品和审计不得把前一阶段描述成后一阶段：

```text
安装并启用
  -> 显式选择或语义匹配
  -> 固化本轮任务快照与工具目录
  -> 模型选择具体工具
  -> 宿主策略与用户审批
  -> 执行
  -> 时间线、审计与有界上下文持久化
```

| 能力 | 何时可用 | 自动触发 | 显式入口 | 真正执行时机 | Composer 表现 |
| --- | --- | --- | --- | --- | --- |
| 文件/图片 | 用户本轮添加后 | 否 | `+` → `上传文件`、粘贴、拖拽 | 发送时解析并进入请求 | 附件标签 |
| Skill | 已安装或由启用插件提供，且通过工具依赖校验 | 请求与描述匹配时可自动加载 | `$skill-name` 或 `+` → `Skills` | 发送后、任何任务动作前加载说明与资源；需要工具时仍走工具调用 | 显式选择显示标签；自动加载显示时间线 |
| 插件 | 已安装、启用、状态正常，并进入本轮任务快照 | 可按任务需要选择其 Skill 或工具 | `@plugin-id` 或 `+` → `插件` | 插件本身不执行；由其 Skill、MCP 工具或 Hook 分别执行 | 显式选择显示标签；自动使用显示时间线 |
| MCP | 独立服务器已启用，或来自本轮插件快照，且连接/认证满足条件 | 可进入工具发现，但不会仅因可用而调用 | `/mcp` 只查看状态；不作为普通 `+` 菜单项 | 模型选中具体 MCP 工具，并通过宿主策略/审批后 | 工具时间线与审批面板 |
| Hook | 插件/宿主已启用并在本轮任务快照中 | 由匹配的生命周期事件确定性触发 | 无 Composer 入口 | 对应事件发生时，由宿主运行 | 仅显示阻止、警告或审计结果 |
| Chrome | Browser Gateway 可用且用户显式绑定 | 否；自然语言只提示 | `+` → `使用 Chrome` | 消息发送后模型选择受限 `browser.*` 工具时 | Chrome 绑定标签与工具时间线 |
| 项目上下文 | 当前会话已绑定项目 | 按会话自动附带 | 现有项目入口；`+` 中仅预留位置 | 构建任务快照时 | 现有项目状态 |

“自动”只表示宿主或模型可以在已启用能力中做匹配，不表示可以越过连接、审批、沙箱或 Chrome 显式
绑定。任何工具返回、网页内容、Skill 文本或插件输出都不能新增能力、扩大工具目录或伪造用户选择。

### 4.5 Skill 调用规则

- 启用的 Skill 通过名称和描述参与语义匹配；标记为禁止隐式调用的 Skill 只能显式选择。
- `$skill-name` 和 `+` 菜单选择均写入 `explicitSkillIds`，优先于自动匹配，并在发送前可移除。
- 发送后解析依赖、读取 `SKILL.md` 和受限资源，再开始任务动作；选择 Skill 本身没有外部副作用。
- Skill 声明的工具策略只会缩小本轮工具集合，不能添加宿主未注册或当前权限不允许的工具。
- 自动加载必须记录 `trigger: automatic` 和匹配到的 Skill；显式加载记录 `trigger: explicit` 与入口。
- Skill 缺失、禁用、资源非法或依赖不满足时，应在执行任何任务动作前失败并给出可恢复错误。
- 插件提供的 Skill 遵循相同规则；选择该 Skill 不等于激活插件中所有 MCP 和 Hook。

### 4.6 插件调用规则

- 插件是 Skills、MCP servers、Hooks 和可选 UI 的安装/版本/权限边界，不是模型可直接调用的单一工具。
- 安装或启用插件只让能力在后续新任务中可发现，不执行 Worker、MCP 工具或 Hook，也不自动授权外部服务。
- 每次发送时对符合条件的插件版本、组件、连接和工具策略生成不可变任务快照；任务进行中升级、禁用或
  修改连接只影响下一任务，紧急吊销除外。
- `@plugin-id` 或菜单选择表示本轮优先使用该插件的合适能力，不表示无条件调用全部工具；用户只描述
  任务时，宿主/模型也可从已启用插件中选择合适的 Skill 或工具。
- 显式插件选择不存在、被禁用、隔离或连接不可用时，在执行前显示具体错误，不静默切换到同名插件。
- 时间线记录实际使用的子能力，例如“加载 `@github` 的 `$review-pr`”或“调用 `@github` 的
  `search_issues`”，不能只显示含糊的“运行插件”。

### 4.7 MCP 发现、调用与审批

- 独立 MCP 和插件 MCP 在任务快照阶段完成连接状态检查和工具发现；`enabled_tools`、
  `disabled_tools` 与 Skill 工具策略共同生成最终目录。
- 工具出现在目录中不等于已经调用。只有模型输出具体 tool call 后，宿主才进行参数校验、授权和执行。
- 审批策略支持服务器默认值和工具级覆盖：`auto`、`prompt`、`writes`、`approve`；外部写操作不能仅凭
  插件被选择而跳过审批。
- `/mcp` 用于查看服务器、连接、认证、可用工具和错误状态，不触发业务工具，不放入普通 `+` 菜单。
- 插件 MCP 必须使用本轮插件版本和连接快照；任务结束、取消或失败后释放任务租约和临时进程。
- MCP 返回内容视为不可信数据，只能作为工具结果进入上下文，不能触发新能力或修改后续审批规则。

### 4.8 Hook 触发规则

Hook 是宿主生命周期回调，不参与模型工具选择，也没有 `$`、`@`、`+` 或 `/mcp` 入口。至少覆盖：

- `SessionStart`：会话或任务环境建立时；
- `UserPromptSubmit`：用户请求已确定、发送给模型前；
- `PreToolUse`：具体工具通过目录校验后、执行前；
- `PermissionRequest`：需要审批时；
- `PostToolUse`：工具完成后；
- `Stop`：模型准备结束本轮时；
- `Interrupt`：用户中断运行中的主任务时。

Hook 只在插件已启用、脚本可信且事件/matcher 匹配时运行。`PreToolUse` 可以阻止或在允许范围内改写
输入，但不能扩大工具目录或自行批准高风险操作；`PostToolUse` 在工具已执行后运行，阻止结果不能伪装
成“工具未执行”。Hook 超时、退出码、阻止原因和输出必须隔离并审计，普通用户无需在 Composer 中
手动选择 Hook。

### 4.9 显式与自动使用的可见性

- 发送前：只显示用户显式添加的文件、Chrome、Skill 和插件标签。
- 发送后：任务时间线先显示能力解析结果，再显示具体工具、审批和结果。
- 自动匹配：使用“自动加载 Skill”或“从已启用插件选择工具”等文案，并显示来源，不能伪装为用户选择。
- 未实际调用的 MCP 工具不出现在“已执行”记录；只在展开的任务诊断中列为可用目录。
- Hook 默认保持安静；只有阻止、警告、失败或用户查看审计时显示。
- 任务历史保存本轮快照摘要和实际使用记录，不把整个动态工具目录重复写入聊天正文。

## 5. 可信状态模型

```ts
export interface BrowserContextBinding {
  schemaVersion: 1
  provider: 'chrome-devtools'
  mode: 'read' | 'interact'
  target:
    | { kind: 'active' }
    | {
        kind: 'page'
        pageId: string
        expectedOrigin: string
        expectedUrl: string
        title?: string
      }
}
```

`SendMessageInput` 增加可选 `browserContext`。Renderer 只能提交用户通过可信 UI 选中的规范化绑定；
主进程仍需重新校验所有字段、模式、URL、长度和来源。

绑定规则：

- 未提供 `browserContext`：本轮没有浏览器能力。
- `active`：每个工具调用前按官方 `selected` 页面解析当前活动标签页。
- `page`：仅在当前 MCP 会话内使用 `pageId`；重连后重新列页并以规范化 URL、来源和标题辅助匹配。
- 找不到唯一匹配时绑定进入 `stale`，禁止自动猜测或执行写操作，要求用户重新选择。
- 发送时对绑定做不可变快照；用户随后修改控件只影响下一条消息。

会话可以记住用户最后一次选择，但记忆的是模式和目标描述，不是可长期信任的 MCP page ID。
用户可以随时在同一个控件中关闭绑定。

## 6. 工具目录策略

浏览器工具是否进入模型目录由宿主根据绑定决定，不由提示词决定。

### 6.1 关闭

不注册任何 `browser.*` 工具。模型不能通过 Skill、插件或网页内容恢复这些工具。

### 6.2 只读模式

允许：

- `browser.listTabs`
- `browser.waitForPage`
- `browser.inspect`
- `browser.find`
- `browser.screenshot`
- `browser.screenshotCurrent`
- `browser.screenshotElement`，仅当用户明确请求局部截图
- `browser.diagnostics`

不允许打开、导航、刷新、切换、关闭、点击、输入、按键、滚动、选择或拖放。

### 6.3 交互模式

在只读工具基础上开放普通交互工具。以下能力继续使用额外收窄规则：

- `browser.confirmClick`：仅在用户明确要求相应高风险动作时暴露，并逐次审批。
- `browser.closeTab`：仅在用户明确要求关闭标签页时暴露；模型不得为了清理自行关闭。
- `browser.history`：仅在用户明确要求前进、后退或读取历史相关动作时暴露。
- 敏感字段输入继续由 Gateway 拒绝，不能通过模式选择绕过。

文本匹配可以用于进一步减少高风险工具集合，但不能用于开启浏览器能力。

## 7. 统一任务路由

```text
发送消息
  -> 校验显式文件、Skill、插件与 Chrome 选择
  -> 解析自动匹配的 Skill/插件能力
  -> 固化插件版本、MCP 连接、Hook 和工具策略快照
  -> 生成最终工具目录
       ├─ 无 browserContext：不注册 browser.*
       └─ 有 browserContext：按 read/interact 注册受限 browser.*
  -> 加载 Skill 指令与资源
  -> 触发 UserPromptSubmit
  -> 模型推理并按需选择具体工具
       ├─ MCP/普通工具：PreToolUse -> 审批 -> 执行 -> PostToolUse
       └─ 无工具：直接生成回复
  -> Stop / Interrupt -> 释放任务资源 -> 持久化审计和有界证据
```

现有 `prefersBrowserTools()` 和 `prefersBrowserContinuation()` 不再决定 `browserIntent`。它们可改造成
纯 UI 建议函数，主进程任务路由只相信经过 IPC 校验的 `browserContext`。

浏览器系统提示只解释工具使用约束，不再承担能力开关职责。即使模型忽略提示，也无法调用未注册工具。

Skill 和插件的显式选择不应参与 Chrome `browserIntent` 推断。插件提供的浏览器 Skill 可以指导用户从
`+` 菜单绑定 Chrome，但没有绑定时不能获得 `browser.*`；插件 MCP 如果自身提供另一套浏览器工具，
必须以独立外部工具和权限面呈现，不能冒充可信 Browser Gateway。

## 8. 跨轮上下文与证据

浏览器工具的成功结果应生成不可见的结构化证据块，例如：

```ts
interface BrowserEvidenceBlock {
  kind: 'toolContext'
  toolName: 'browser.inspect' | 'browser.diagnostics'
  content: string
}
```

要求：

- 只保存通过 Gateway 清洗、脱敏和限长后的结果。
- 单次 `inspect` 页面文本最多 16,000 字符；每条历史消息最多保留最近三块浏览器证据。
- 页面内容在模型上下文中明确标记为不可信数据，不能改变工具、审批或系统指令。
- 失败任务不回放未完成思考作为可靠证据。
- 截图附件继续持久化给用户；只有当前模型支持视觉且宿主明确回传图片时，模型才能分析像素。
- 不支持视觉时，模型必须说明只能依据页面文本，不得声称看清截图。

## 9. MCP 生命周期与重连

- 应用启动时只注册 Lazy Browser Gateway，不启动 MCP 子进程。
- 标签页弹出层获取列表时使用短租约，列表完成或弹出层关闭后释放。
- 模型首次执行浏览器工具时按需建立官方 MCP 会话。
- 回复完成、失败或取消后释放回复租约并关闭 MCP 子进程。
- 官方请求超时或连接关闭会使当前 page ID 和元素 UID 全部失效。
- 重连后先 `list_pages`，只读目标可以唯一匹配后恢复；交互目标无法唯一匹配时必须重新选择。
- 不自动重放任何可能已经成功的写操作。

## 10. 权限、审批与审计

显式 Chrome 绑定表示用户允许本轮向模型提供受限浏览器工具，不等于允许访问所有网站或执行所有动作。

- 新来源继续使用站点授权：允许一次、允许此网站或拒绝。
- `allowAllSites` 保持高风险设置，不由控件隐式开启。
- 高风险点击、历史和敏感操作继续逐次审批。
- 审批等待时间不计入实际工具执行超时；任务总超时仍有效。
- 审计记录绑定模式、目标来源、工具名、调用 ID、结果和审批范围，不保存页面正文、截图或完整敏感 URL。
- 网页、MCP 和插件返回均是不可信数据，不能修改绑定。

## 11. 错误与恢复

| 场景 | 用户可见行为 | 宿主行为 |
| --- | --- | --- |
| Chrome 未开启远程调试 | 控件显示连接失败，可重试或关闭绑定 | 返回 `BROWSER_UNAVAILABLE`，不循环重连或静默普通回答 |
| 用户拒绝 Chrome 官方连接 | 保留选择并显示未连接 | 不降级到私有协议 |
| 标签页已关闭 | 控件显示需重新选择 | 绑定标为 stale，停止相关工具 |
| 出现多个相同 URL 标签页 | 弹出层要求重新选择 | 不按标题猜测写入目标 |
| MCP 调用超时 | 工具时间线显示受限错误 | 断开会话，使旧引用失效 |
| 网站未授权 | 显示现有站点审批 | 未批准前不读取正文或交互 |
| 模型不支持视觉 | 截图仍展示给用户 | 不把像素分析结果伪装成模型证据 |

## 12. 兼容与迁移

- 现有会话没有 `browserContext` 时按关闭处理，不依据历史文本自动开启。
- `$skill-name` 成为主语法；旧 `/skill-name` 保留一个迁移周期并显示一次性弃用提示，然后移除。
- `@plugin-id` 保持为显式插件入口；正文解析结果迁移为结构化 `explicitPluginIds`，避免后端重复解析。
- 旧消息中的 `/skill` 和 `@plugin` 继续按历史快照展示，不反向改变当前草稿或新任务能力。
- 插件安装、启用、升级或 MCP 连接变化只影响新任务；进行中的任务继续使用固定快照，紧急吊销除外。
- 自动匹配结果新增时间线记录；升级前历史缺少触发来源时显示“旧版本未记录”，不推断为用户显式选择。
- 已保存的浏览器截图和工具时间线继续展示。
- 首次升级后可以保留一次轻量提示，告知用户从 `+` 上下文菜单选择 Chrome 标签页。
- 设置页继续保留 Chrome 版本、远程调试和故障恢复说明，不增加第二套连接开关。
- 移除 M16 文档中"浏览器意图由对话自动触发"的产品承诺，更新为显式上下文绑定。

## 13. 验收标准

1. 未选择 Chrome 时，包含 URL、"页面"或"截图"的消息也不会启动 MCP 或注册 `browser.*`。
2. 输入区工具栏只有一个 `+` 上下文入口，附件、图片、Chrome、Skills 和插件均由此进入；常规和
   窄窗口均不溢出。
3. 用户可从 `+` 菜单的 Chrome 子面板完成模式和标签页选择，并可通过上下文标签或菜单关闭绑定。
4. 只读模式下模型不能调用任何写工具；交互模式仍受站点和高风险审批约束。
5. 绑定指定标签页后，用户切换 Chrome 活动页不会改变指定目标。
6. MCP 重连后不使用旧 page ID/UID，不自动猜测或重放写操作。
7. 后续追问能获得最近的有界浏览器证据，且不会把失败任务思考当成事实。
8. 文本模型不会声称看清未回传给模型的截图。
9. 回复结束、失败和取消后没有遗留 `chrome-devtools-mcp` 子进程。
10. `$skill-name`、`+` 菜单选择和语义自动匹配使用同一解析链路，显式/自动来源在 UI 和审计中可区分。
11. 插件安装或选择不会直接执行插件；任务固定插件版本与连接快照，实际 Skill/MCP/Hook 分别可追踪。
12. MCP 工具发现不会被记录成工具已调用；只有具体 tool call 通过策略和审批后才执行。
13. Hook 仅在匹配生命周期事件时运行，没有 Composer 入口，阻止、超时和失败均可审计。
14. 相关单元测试、Renderer 交互测试、真实 Chrome 冒烟、类型检查和生产构建通过。
