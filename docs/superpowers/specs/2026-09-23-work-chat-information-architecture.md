# ASTRYVE「工作 / 对话」分治与会话归属设计

> 状态：产品归属与切换规则已确认；批次 3A 代码已接入，旧 MySQL 隔离迁移与主要真实桌面交互已验证，真实模型/后台任务等余项未完成。总实施顺序以 `docs/08-第四阶段计划.md` 为准。
>
> 日期：2026-09-23。此文只定义 ASTRYVE 的产品行为，不把其他产品的界面或权限实现当作本项目的技术契约。

## 1. 目标和当前差距

顶部提供两个一级入口：**工作**与**对话**。工作按项目组织会话；没有项目的会话集中放在侧栏最下方的「普通对话」区域，并归属「对话」入口。两类入口共享消息、附件、搜索、Skill、插件和经授权的 Chrome 能力基础，但「对话」不提供 Coding。

立项时只有一份按日期分组的会话列表和可变的 `projectPath`；新建、恢复和项目选择没有类型概念。仅改侧栏会导致普通对话权限漂移。因此实施顺序先改数据契约与主进程能力边界，再改导航；当前代码进度与未完成验收以总计划和 `docs/verification/2026-09-24-3A-验收进展.md` 为准。

## 2. 信息架构

- 顶部「工作 / 对话」是一级空间切换，不是两个模型、两个数据库，也不是现有的单会话标题标签。从当前会话切换到另一类对话时，直接新建目标类型的空白会话，原会话及其草稿、滚动位置保留在原分组；以后从历史列表选择原会话可继续。生成中的任务不因切页被取消，后台审批仍显示来源。仅为查看历史而选择已有会话，不额外新建。
- 「工作」侧栏按已授权项目分组：项目 A → 该项目的所有会话；项目 B → 该项目的所有会话。项目组可折叠，组内按最近活动排序；项目名称可同名，辅以完整路径辨认。项目下既可有 Coding 任务，也可有只讨论该项目的会话，不按消息正文或是否调用过工具来分类。
- 侧栏始终先列各项目组，再把无项目普通会话集中放在最下方；「对话」入口选中的是普通会话，不重复渲染另一份列表。搜索覆盖全部会话，结果仍标明项目或普通对话来源，点击后切到正确入口。
- 新建「工作」先选/授权项目，然后创建带项目归属的会话；从某项目组点「新建」直接带入该项目。新建「对话」不选择项目。项目选择不应再是普通对话标题栏里的隐式权限升级入口。
- 右侧文件树、diff、终端和项目权限设置只在工作会话且项目授权有效时出现；普通对话保留消息、附件、浏览器证据等通用展示。现有顶部会话标题/关闭按钮应与一级「工作 / 对话」切换区分；关闭仅关闭视图，不创建新会话，也不删除历史。

## 3. 会话身份与迁移

- 会话持久化显式 `kind: 'work' | 'chat'`，并保存规范化的项目身份（优先稳定 `workspaceId`，路径作为展示/恢复信息）。`work` 必须有有效项目归属；`chat` 不得有项目归属。主进程创建、读取、发送与工具调用均验证此不变量，不信任渲染层传入的类型或工具列表。
- 类型和项目归属对会话保持固定。需要「把普通讨论带入项目」时，显式选择项目并**新建**工作会话；从工作切到普通对话也**新建**无项目会话。原会话及历史保留，不迁移消息、证据、审批或权限，不静默复制摘要。工作会话改项目同样新建会话。空白且无消息的会话只可在相同类型和项目下复用。
- 一次性迁移旧记录：有可信 `projectPath` 且能对应已授权项目的记录归 `work`；无项目路径归 `chat`；路径失效或无法确认授权的记录保留历史并标记待重新绑定，不自动给予 Coding 权限，也不把已有消息删除或悄悄降级为普通对话。迁移可重复执行，SQLite/MySQL/旧 JSON 导入路径一致。
- 项目从最近列表移除、目录失效或授权撤销时，历史仍可查看；发送与项目工具暂停，提示重新授权/绑定。用户删除项目组不等于删除其会话，删除会话仍是单独确认操作。
- 固定的 `kind`、项目身份和每次发送时的授权快照共同决定能力目录；左侧位置、会话标题、聊天正文、网页或插件内容都不能改变权限。

## 4. 能力边界

### 普通对话（`chat`）

保留：普通多轮问答、图片/文档输入与历史、模型支持的搜索、非项目 Skill、符合策略的插件/外部 MCP、经模型选择并由宿主授权的 Google 官方 Chrome DevTools MCP、截图/证据预览，以及消息级审批与审计。能力依模型原生工具支持情况可用；不支持时明确降级，不伪造调用。

禁止：项目工作区读取/搜索、代码修改与补丁、diff、终端/命令、Git 操作、项目专属 Skill，以及任何借插件或 Chrome 结果获得本地项目权限的路径。无项目隔离临时目录仅用于能力运行时内部工作，不能被暴露成可供模型 Coding 的工作区。声明本地工作区读写或进程权限的插件不进入普通对话工具快照；无法确认效果时默认不开放。用户讨论代码、粘贴片段或上传文件仍是普通对话，不等于授予 Coding。

插件清单权限过滤是模型可见工具与宿主授权边界，不等于对第三方本地插件代码的操作系统级沙箱；任意已安装插件的代码信任问题仍受 P4 插件威胁模型约束，不能把本次分治宣称为恶意插件的完整隔离。

### 项目工作（`work`）

在普通对话通用能力之上，按项目授权、Policy Engine 与逐次审批提供项目观察、文件操作、补丁、diff、终端和 Git 等 Coding 能力。模型是否实际调用 Coding 由任务需要决定；进入工作入口不等于每轮执行代码，也不应强迫工具调用。Chrome 与项目工具可以在同一任务中组合，但网页内容不能扩大本地项目权限。

两类会话的隔离必须在主进程工具目录、实际执行入口和审计三处落实；仅隐藏 UI 按钮不构成隔离。模型提供的工具名、结构化参数、历史记录与插件回包均不得升级 `chat` 的能力。

## 5. 实施与验收切片

1. 先定义 `kind`/项目身份与旧记录迁移；修复当前空白会话复用逻辑，复用必须同时匹配类型和项目，不得跨组抢用空白会话。
2. 主进程按类型建立工具快照并验证执行；普通对话访问 workspace/patch/terminal/git 的直接 IPC 与插件间接路径都应拒绝。补齐取消、审批、切换入口和项目失效的测试。
3. 增加一级切换、按项目分组和底部普通对话区；新建、搜索、恢复、快捷键、删除/关闭和后台状态均按归属工作。
4. 在上述边界稳定后继续统一模型驱动循环、`browser.activate` 和 Chrome 正确性；Chrome 不因「对话」模式被整体禁用。
5. 验收至少覆盖：旧数据迁移与重启、同名项目、空白会话跨组复用、项目授权撤销、普通对话请求改代码、插件伪装 Coding、工作中只聊天、两入口并发生成/审批、搜索跳转和截图恢复。

## 6. 已确认的产品决定

1. 用户确认类型固定；切换到另一类对话直接开新会话，原记录不转换、不删除。切到「工作」须先选定项目，切到「对话」创建无项目会话。
2. 用户确认只要绑定项目就归于「工作」，包括不使用 Coding 的项目讨论；无项目会话统一归于「对话」。

实施迁移时仍须先验证旧数据映射、备份与回滚；产品选择已定不等于允许无验证地改写历史。
