# AI Agent 插件与浏览器能力平台设计

> 状态更新（2026-09-13）：本文中的插件平台设计继续有效；“应用启动独立 Chrome”方案已取消并从代码移除，“当前 Chrome 配套扩展”迁移至独立项目。当前仓库只保留 Browser Gateway、标准工具、权限审批和审计等浏览器中立协议，等待外部扩展适配器接入。本文后续凡要求独立 Chrome、双浏览器模式或在本仓库交付扩展的文字均为历史方案，不再具有实施约束。

> 状态：已确认，待实施计划  
> 日期：2026-09-09  
> 适用阶段：P4 / M12-M17
> 前置基础：M9 Skills；M10 Renderer Sandbox 的安全边界与隔离能力

## 1. 背景

项目已经具备 Skills 管理、工具注册、任务运行时、权限审批和审计能力，但当前 Skills 主要是声明式工作流，不能安全地提供任意第三方运行时代码，也没有统一的浏览器控制通道。

本设计新增一个插件平台，使模型可以自主选择已启用插件，也允许用户通过 `@插件` 显式指定插件。插件可以组合 Skills、MCP 工具、生命周期 Hooks、资源与可选 UI。浏览器能力由宿主统一提供，普通插件不能直接连接 Chrome 调试端口或注入任意浏览器扩展。

浏览器能力现按适配器中立方式保留；当前仓库不启动或管理 Chrome，也不在未连接适配器时向模型注册浏览器工具。用户当前 Chrome 的扩展和连接适配由独立项目交付。

## 2. 目标

- 支持标准 `plugin.json` 插件包，并兼容旧 `.codex-plugin/plugin.json`。
- 支持 Skills、MCP 服务、Hooks、资源和可选插件 UI。
- 第三方可执行代码在隔离进程中运行，不进入 Electron 主进程。
- 支持官方市场、社区市场、GitHub 市场源和本地 ZIP/文件夹导入。
- 支持模型自主选择插件以及 `@插件` 显式指定。
- 为插件提供统一、可审批、可审计的浏览器工具。
- 保留可供外部浏览器适配器复用的 Gateway、工具、审批、脱敏和审计协议。
- 当前 Chrome 及已登录页面的控制能力由独立扩展项目实现并单独验收。
- 页面在常规窗口和窄窗口下均保持清晰可用。
- 每完成一个 M，提交独立的 Markdown 页面验证测试单。

## 3. 非目标

- 不允许市场插件把代码直接加载进 Electron 主进程或 Renderer。
- M11-M13 不允许普通插件携带并安装任意 Chrome 扩展代码。
- 不复制用户日常 Chrome 的 Cookie、密码、历史或默认资料目录。
- 不在第一版建设完整的商业结算、作者分成或公开投稿后台。
- 不保证导入任意第三方 Codex 插件后无需适配即可运行；只保证清单和标准组件的兼容读取。
- 不把自动化测试视为人工页面验收的替代品。

## 4. 已确认的产品决策

1. 插件使用沙箱包模型。
2. 当前仓库不创建或管理独立 Chrome 资料。
3. 浏览器操作采用按风险分级审批。
4. 插件来源分为官方、社区、GitHub 市场源和本地开发者插件。
5. 浏览器能力采用统一宿主桥接；普通插件不能自行注入 Chrome 扩展。
6. 新插件默认使用标准 `plugin.json`，兼容旧 `.codex-plugin/plugin.json`。
7. 插件支持模型自动选择与 `@插件` 显式选择；Skills 继续使用 `/skill`。
8. 浏览器能力只有在外部适配器已连接时才可注册；Chrome 扩展不在当前仓库交付。
9. 设置侧栏使用一个“插件”入口，页面内部以“插件 / 技能”顶层标签区分两类能力；不再为 Skills 单独占用侧栏入口。

## 5. 总体架构

```text
Conversation / Agent Runtime
            │
            ▼
    Unified Tool Catalog
            │
            ├── Built-in tools
            ├── Skills
            └── Plugin Host
                  │
                  ├── MCP connections
                  ├── Sandboxed local plugin workers
                  ├── Lifecycle hooks
                  ├── Optional UI resources
                  └── Browser Capability Gateway
                         └── External adapter (not bundled)
```

### 5.1 Agent Runtime

现有 Agent Runtime 仍是模型工具调用的唯一入口。Plugin Host 只把通过校验且已启用的工具描述注册到统一工具目录中。模型不会得到插件内部进程地址、Chrome 调试端口或明文凭据。

### 5.2 Plugin Host

Plugin Host 负责：

- 插件发现、解析、兼容转换和状态管理。
- 安装、更新、启用、禁用、卸载与故障隔离。
- 权限清单校验与工具级授权。
- MCP 连接、认证状态和工具发现。
- 本地插件 Worker 的创建、通信、超时、取消和回收。
- Hooks 的受控注册与执行。
- 插件调用记录、错误和资源使用审计。

### 5.3 沙箱 Worker

每个本地可执行插件使用独立 Utility Process。Worker 只能通过类型化 IPC 调用宿主公开的能力，默认没有主进程对象、Renderer DOM、任意文件系统、任意网络或系统命令访问。

插件崩溃不影响主程序。连续启动失败、协议违规、超限或异常退出后，插件进入“已隔离”状态，由用户查看诊断后手动恢复。

### 5.4 Browser Capability Gateway

Browser Gateway 是所有浏览器操作的唯一入口，负责：

- 浏览器会话和标签页管理。
- 标准化 DOM、语义树、截图和交互工具。
- 网站权限、敏感字段、高风险动作审批。
- 元素引用、页面版本和失效检测。
- 调用超时、取消、并发控制和审计。
- 屏蔽外部浏览器适配器的连接差异。

## 6. 插件包规范

### 6.1 目录结构

```text
example-plugin/
├── plugin.json
├── skills/
├── mcp.json
├── hooks/
├── scripts/
├── assets/
└── ui/
```

只有 `plugin.json` 必需。其余目录按插件能力选配。

### 6.2 清单字段

清单至少包含：

- 稳定插件 ID、名称、版本、作者、说明和图标。
- Skills、MCP、Hooks、资源与可选 UI 的入口。
- 最低 AI Agent 版本、平台和架构限制。
- 文件、网络、命令、浏览器、剪贴板等权限。
- 更新地址、内容摘要和可选发布者签名。
- 是否仅桌面可用、是否需要 Chrome、是否需要外部账号。

AI Agent 专属字段放入 `extensions.aiAgent`。兼容读取 `.codex-plugin/plugin.json` 时，先转换为内部规范化清单，再进入同一校验流程。

### 6.3 浏览器权限

浏览器权限按能力与域名拆分：

- 页面可见文本和语义树。
- DOM 摘要和元素属性。
- 页面或元素截图。
- 点击、悬浮、滚动和普通文本输入。
- 导航、新建或关闭标签页。
- 上传、下载和文件选择器。
- 浏览历史。
- Cookie 与站点存储。

Cookie 与站点存储默认不向插件开放。浏览历史始终为单次审批能力，不提供永久允许。

## 7. 来源与信任模型

### 7.1 官方市场

- 由项目维护方审核和签名。
- 支持自动更新。
- 展示“已验证”标识。

### 7.2 社区市场

- 展示作者、源码、版本、权限和审核状态。
- 未审核条目不得伪装为官方或已验证。
- 是否允许自动更新由签名和用户设置共同决定。

### 7.3 GitHub 市场源

- 用户添加仓库市场索引。
- 支持手动同步、错误提示和来源禁用。
- 更新前重新校验索引、包摘要和权限差异。

### 7.4 本地开发者插件

- 支持导入 ZIP 或本地文件夹。
- 显示“本地 / 未审核 / 开发者模式”。
- 默认不自动更新。
- 文件夹模式支持显式“重新加载”，但不在后台静默热重载正在运行的工具。

来源只决定信任提示与默认策略，不改变插件包格式或权限校验过程。

## 8. 安装与生命周期

### 8.1 安装

1. 将包读取到临时隔离目录。
2. 检查路径穿越、链接逃逸、文件数量、单文件大小、总大小和压缩炸弹。
3. 解析并规范化清单。
4. 检查应用版本、平台和依赖兼容性。
5. 计算内容摘要并校验签名。
6. 检查实际组件是否超出清单声明。
7. 展示能力、数据目标、权限、发布者与来源摘要。
8. 用户确认后原子安装，失败时不留下半安装状态。
9. 需要账号的 MCP 插件进入“待连接”。

### 8.2 状态

插件状态包括：

- 已安装
- 已启用
- 已禁用
- 待连接
- 权限受限
- 更新可用
- 已隔离
- 启动失败

### 8.3 上下文生效

- 新任务使用安装时最新的已启用插件快照。
- 已有任务不在后台静默改变工具集合。
- 已有任务显示“插件已变化，重新加载工具”。
- 重新加载后更新工具目录，但不删除既有对话和审计记录。
- 用户用 `@插件` 显式指定时，未安装、未启用或未连接状态必须在发送前反馈。

### 8.4 更新

更新页展示版本变化、权限差异、发布者、摘要和更新说明。

- 签名一致且没有新增权限时，可以按用户设置自动更新。
- 新增或扩大权限时必须重新批准。
- 签名主体改变时视为新发布者，不得静默升级。
- 更新失败时继续保留上一可用版本。

### 8.5 卸载

- 停止新的调用并等待或取消当前调用。
- 终止插件 Worker，并从新任务工具目录移除。
- 删除插件文件。
- 凭据和缓存由用户选择保留或清除。
- 保留历史聊天与审计记录。
- 工作区或管理员预装插件可限制卸载，仅允许禁用。

## 9. 凭据与认证

- API Key、OAuth Token 和刷新令牌存储在操作系统凭据库中。
- 插件只得到短期授权句柄，不读取明文凭据。
- MCP 连接使用服务自身的认证和访问控制。
- 工具调用前同时检查插件权限、当前任务权限和外部账号状态。
- 卸载插件不会默认断开共享的外部连接，界面需要明确说明并提供单独断开入口。

## 10. 对话触发与工具选择

### 10.1 自动选择

Agent Runtime 可以根据插件名称、说明、工具模式和当前任务自动选择已启用插件。仅把候选工具的必要描述加入模型上下文，避免一次注入全部插件内容。

### 10.2 显式选择

- 输入 `@` 打开插件与浏览器候选。
- 支持方向键、Enter、Esc 和点击外部关闭。
- 选中后在输入框上方显示可移除标签。
- Skills 继续通过 `/skill` 触发。
- 回复顶部只显示简短“正在使用”状态，具体调用放入工具时间线。
- 界面持续显示实际模型名称。

## 11. 浏览器方案（历史，已废止）

### 11.1 独立 Chrome（已取消）

- 应用启动 Chrome，并指定非默认的专用用户资料目录。
- 首次登录由用户在可见浏览器中手动完成。
- 后续保留专用会话，但不复制日常 Chrome 数据。
- 支持启动、关闭、重启和清除专用浏览数据。
- 不向插件暴露原始 CDP 地址和认证信息。
- 浏览器崩溃后可以恢复任务，但不会自动重复高风险提交动作。

### 11.2 当前 Chrome 配套扩展（迁移至独立项目）

- 开发一个 AI Agent 官方 Chrome 扩展。
- 使用受认证的本地通信通道与桌面应用配对。
- 支持 `@Chrome`、当前标签页和具体标签页提及。
- 支持把页面、选中文字和截图加入任务上下文。
- 扩展显示连接、受控、暂停和断开状态。
- 用户可以在浏览器侧立即暂停或断开控制。
- 普通市场插件只能调用 Browser Gateway，不能获得配套扩展的底层通道。

## 12. 标准浏览器工具

### 12.1 会话与导航

- 启动、关闭、重启浏览器。
- 列出窗口与标签页。
- 新建、选择和关闭标签页。
- 打开地址、前进、后退、刷新和等待页面稳定。

### 12.2 审查与定位

- 获取标题、URL、页面元信息和可见文本。
- 获取受限大小的 DOM 摘要或语义树。
- 按角色、标签、文本、CSS 和稳定元素引用定位。
- 获取元素属性、可见性、状态和边界框。
- 获取控制台错误、失败请求和性能摘要。

### 12.3 交互

- 点击、双击、悬浮、滚动、拖放。
- 输入普通文本、清空、选择和键盘操作。
- 处理下拉框、复选框和单选框。
- 在审批后处理上传、下载和文件选择器。

### 12.4 视觉

- 页面截图和元素截图。
- 高亮将要操作的元素。
- 截图结果限制尺寸，并支持按需提高细节。

工具返回稳定元素引用与页面版本。导航或页面大幅变化后，旧引用失效，调用方必须重新定位，防止点击错误目标。

## 13. 权限与审批

### 13.1 网站权限

首次使用新域名时提供：

- 仅允许一次
- 始终允许此网站
- 拒绝

设置页维护允许列表和阻止列表。允许所有网站属于高风险设置，不作为默认选项。

### 13.2 动作风险

- 已授权网站内的读取、截图、滚动：低风险，可自动执行。
- 普通字段输入：中风险，可按任务策略自动执行。
- 密码、支付、验证码和敏感字段：不得回传模型，必要时由用户接管输入。
- 发送、发布、删除、提交表单、上传、下载、购买和支付：高风险，执行前审批。
- 浏览历史：每次单独审批，不允许永久授权。

### 13.3 审批界面

审批弹窗使用项目自定义组件，不使用 Windows 原生长文本弹窗。默认只展示：

- 动作
- 目标
- 实际影响

完整工具名、参数、插件和权限依据放在折叠详情中。文案有最大高度，超出后内部滚动，不覆盖整个屏幕。

### 13.4 不可信内容

网页内容、插件返回值和外部数据始终标记为不可信上下文。它们不能修改系统指令、权限、审批策略、插件清单或工具注册。

## 14. 超时、并发与恢复

- 每个调用具有唯一 ID、截止时间和取消信号。
- DOM、截图、控制台和网络结果设定大小上限，超限时摘要或分页。
- 页面无响应不能阻塞 Agent 主循环或 Renderer。
- 同一标签页的写操作串行执行，安全读取可并发。
- 用户可以随时暂停整个浏览器会话。
- 插件 Worker 心跳失败后终止并进入重启/隔离流程。
- 应用关闭时清理子进程、调试端口、临时文件和未完成调用。
- 对高风险操作使用幂等或执行确认标记，恢复后不自动重放。

## 15. 用户界面

### 15.1 统一扩展中心

设置侧栏增加一个“插件”入口，页面顶部固定提供“插件 / 技能”两个标签：

- 插件标签管理可执行插件、外部服务和浏览器能力。
- 技能标签承载现有 Skills 的发现、搜索、安装、启停、更新和卸载。
- 两类能力不混为同一列表；`@插件` 与 `/skill` 的触发语义保持独立。
- 插件后端尚未接入时只展示真实空状态，不使用虚假市场数据或可误操作的安装入口。

插件标签后续包含：

- 已安装
- 插件市场
- 市场源
- 开发者

已安装页提供搜索、来源筛选、启停、更新和卸载。市场页按推荐、官方、社区和分类浏览。市场源页管理官方与 GitHub 源。开发者页负责本地 ZIP/文件夹导入、重载和诊断。

插件详情页展示能力、Skills、工具、浏览器权限、数据发送目标、版本、作者、来源、签名和更新记录。

### 15.2 浏览器设置（历史，已取消）

设置中增加独立“浏览器”栏，包含：

- 独立 Chrome 的安装、资料和清理。
- 当前 Chrome 配套扩展的安装、配对和连接状态。
- 网站允许列表和阻止列表。
- 历史、上传、下载等敏感能力。
- 当前受控标签页、调用插件和立即断开。

### 15.3 响应式布局

- 常规窗口使用居中内容区和详情页。
- 窄窗口切换单列，设置导航可折叠。
- 插件详情使用覆盖式页面或抽屉，不压窄主列表。
- 表单、标签和权限说明不能依赖固定宽度。
- 所有弹窗限制最大宽高并支持内部滚动。

## 16. 审计与隐私

工具时间线和审计记录至少包含：

- 任务和调用 ID。
- 实际模型名称。
- 插件 ID、版本和来源。
- 工具名称、目标网站和风险等级。
- 审批选择与作用范围。
- 开始、结束、取消、失败和超时状态。
- 结果摘要，不默认保存完整敏感页面内容。

浏览器活动仅在成为任务上下文、工具记录或用户明确保存的证据时持久化。凭据、密码字段和完整 Cookie 不进入对话历史。

## 17. 里程碑

### M12：统一扩展中心页面

- 设置侧栏合并为单一“插件”入口。
- 页面顶部提供“插件 / 技能”标签切换。
- 迁入现有真实 Skills 管理能力，保留搜索、市场、导入和启停操作。
- 插件标签提供真实空状态、搜索和后续添加入口占位，不伪造插件数据。
- 常规窗口和窄窗口响应式回归。

## 19. 实施门槛

- M12 只建设统一扩展中心页面，不接入虚假的插件数据或执行入口。
- M10 Renderer Sandbox 尚未完成时，M13 可以先实现清单和数据模型，但本地可执行 Worker 必须等待 M10 隔离协议稳定，禁止临时把插件代码放进主进程。
- M13 完成后才能让市场插件真实进入 Agent 工具目录。
- M14 完成后才能默认开放远程市场安装。
- 只有外部适配器已连接且通过审批时，才能向模型注册插件声明的浏览器能力。
- 用户当前 Chrome 能力以独立扩展项目通过验收并完成后续集成为前提。
- M17 通过前，不将社区插件或“允许所有网站”设为默认推荐。

## 20. 参考基线

- OpenAI Agent Plugins：插件组合 Skills、MCP、Hooks 和可选 UI。
- Codex/ChatGPT 插件目录：区分公共、工作区和个人来源，并对安装、连接、启停和卸载进行管理。
- ChatGPT 浏览器扩展：由统一官方扩展连接日常浏览器，通过站点授权、允许列表、阻止列表和审批控制风险。
- Chrome：当前仓库不启动调试实例；浏览器连接和最小权限要求由独立扩展项目定义。
