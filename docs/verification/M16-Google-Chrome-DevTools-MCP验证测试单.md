## 本轮自动化实测

运行 `npm run smoke:browser-mcp`，通过官方 stdio MCP 真实连接已开启远程调试的
Chrome，且仅操作临时本机页面。以下链路已通过：

- 官方工具发现（共至少 24 个工具）与 `list_pages`；
- `new_page`、`take_snapshot` 及官方 UID；
- `fill`、`click`、`evaluate_script`；
- `take_screenshot`；
- `list_console_messages`、`list_network_requests`；
- `navigate_page` 刷新；
- 先用 `select_page` 切换内部选中页，再用 `close_page` 关闭测试页；
- 客户端、官方 MCP 子进程与临时 HTTP 服务正常退出。
- 对话中的明确浏览器请求会按需启动官方连接；无需在设置页手动开启。每轮回复结束自动断开，
  启动应用本身不会提前启动 MCP 或触发授权提示。

真实验证发现并修复：关闭当前选中页前必须先选择其他页；最后一页按 Google 官方
工具约束不允许关闭。未在本轮自动化覆盖的人工验收项继续保持未勾选。

## 七、用户回归步骤（需人在 Chrome 前）

1. 启动 Chrome 144+，打开 `chrome://inspect/#remote-debugging` 并启用远程调试。
2. 启动 ASTRYVE，新建普通对话，直接发送“用 Chrome 打开 https://example.com 并截图”；
   不进入设置页，也不操作任何连接开关。
3. Chrome 首次显示官方远程调试批准弹窗时点击允许。确认只打开一个目标标签页，等待期间不重复
   打开或刷新；回复中应出现可点击、可放大缩小的截图。
4. 离开该对话再重新进入，确认文字与截图都保留。
5. 在同一对话再次发送“读取当前页面标题并再截一张图”，确认第二次调用成功。
6. 回复结束后检查任务管理器，不应有残留的 `chrome-devtools-mcp` 子进程。
