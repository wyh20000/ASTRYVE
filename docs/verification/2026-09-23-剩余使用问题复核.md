## P1：下一批先处理

1. **普通问答仍默认联网。** `src/main/ipc/message.ts` 的 `useSearch` 只检查非图片、非 Agent 和供应商能力（约第 420 行），随后优先走供应商搜索流（约第 843–845 行），没有检查本轮是否需要联网。普通问答可能额外联网、变慢，搜索失败时再回退。批次 3 应默认不联网；只允许模型原生调用或用户结构化选择后搜索，并测试普通问答零 search。
2. **图片输入排斥其他能力。** 同文件的 `projectEligible = !vision`（约第 301 行）同时阻断项目任务和浏览器任务创建；即便本轮选择了插件，带图时也不会启动对应任务。批次 3 应让多模态输入与项目、Skill、插件、Chrome 能力组合，并分别接受原有权限约束；测试“图片 + 项目”“图片 + 插件”“图片 + 浏览器”。
3. **浏览器任务仍由关键词路由。** `src/main/ipc/message.ts` 约第 319–322 行调用 `prefersBrowserTools()` / `prefersBrowserContinuation()` 决定任务创建，规则在 `src/main/services/browser/browserConversation.ts`。模型在未命中正则的普通对话中没有自行激活浏览器的机会；正则命中也可能启动不需要的任务。批次 3/4 应将决定权交给模型的原生激活工具，宿主只执行授权、绑定与审计；普通问答不得连接 Chrome。

前三项是同一个路由问题，不建议分别追加新的关键词补丁。

## P2：能力主链路稳定后收口

4. **跨会话审批缺少来源提示。** `src/renderer/src/components/chat/ApprovalDialog.tsx` 约第 9–16 行从所有会话挑选最新审批；弹窗显示操作和目标，却没有会话名称。用户在 A 会话阅读时可能看到 B 会话审批。批次 5 应显示会话、任务、项目与工具来源；后台会话增加 badge，并验证过期和会话切换。
5. **首次历史读取失败会伪装为空对话。** `src/renderer/src/stores/chatStore.ts` 的 `load()` 仅在 `res.ok` 时更新消息（约第 80–88 行），失败没有会话内错误态或重试入口。批次 6 应区分“尚无消息”和“加载失败”，保留现有内容并允许重试。
6. **删除会话后前端聊天缓存未清理。** `src/renderer/src/stores/sessionStore.ts` 的 `remove()` 清理草稿和会话列表（约第 76–86 行），但没有移除 `chatStore` 中该 ID 的消息、发送状态、补充提问和审批请求。批次 5/6 应在删除成功后按 session 清理全部 UI 状态，并阻止迟到事件把已删除会话重新插入缓存。
7. **长会话读路径仍全量扫描。** SQLite 已解决整库写入问题，但 `buildHistory()` 仍从 `listMessages(sessionId)` 取整段历史（`src/main/ipc/message.ts` 约第 479 行）；启动/删除清理也逐会话读取全部消息（`src/main/db/index.ts` 约第 77–95 行）。批次 7 需测 10,000 条消息下的真实发送、启动和删除延迟，再按数据决定是否引入最近轮次查询、来源索引或后台清理。现有测试主要证明分页与增量写入，不应宣称长会话端到端性能已经验收。
